# 第二部分：I2C（最先背，最高频）

## 2.1 是什么
**Inter-Integrated Circuit**，Philips（现 NXP）提出。两根线：
- **SDA**（Serial Data）：数据线
- **SCL**（Serial Clock）：时钟线

多主多从，靠 **7 位地址** 区分从机（可用约 112 个地址，另有 10 位扩展寻址）。

## 2.2 电气结构：开漏 + 上拉 ★★（必答"为什么"）
两根线都是**开漏输出（open-drain）**：器件只能主动**拉低**，不能主动输出高电平；高电平靠**上拉电阻**。

**两个后果（这就是考点）**：
1. 多个器件同时拉线**不会短路**（都拉低就是低，不会像推挽那样一边高一边低烧管子）
2. 总线是**线与逻辑**（wired-AND）——任何一方拉低，整条线就是低。**这是 ACK 应答和多主仲裁的物理基础**

**上拉阻值**：100kHz 用 4.7kΩ，400kHz 用 2.2kΩ（速度越快，边沿要越陡，阻值要越小）。

## 2.3 时序三要素（必须能画）★★★

```
        START              数据位有效区                    STOP
         ↓                                              ↑
SCL: ‾‾‾‾‾\______/‾‾‾‾\______/‾‾‾‾\______/‾‾‾‾‾‾‾‾‾‾‾‾‾
SDA: ‾‾‾‾‾‾‾‾\________/‾‾‾‾‾\________/‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾
          SDA高→低              SDA低→高
       （SCL 为高时）        （SCL 为高时）
```

1. **起始条件 START**：**SCL 为高电平**时，**SDA 由高变低**
2. **数据有效**：SDA **只能在 SCL 低电平期间变化**；**SCL 高电平期间 SDA 必须保持稳定**
3. **停止条件 STOP**：**SCL 为高电平**时，**SDA 由低变高**

## 2.4 为什么 SDA 在 SCL 高电平期间必须稳定？★★（关键分差）
因为 **SCL 高电平期间 SDA 的跳变被定义为起始/停止信号**。如果数据位在这个窗口内翻转，接收方会误判成起始或停止，导致帧错位、通信失败。

→ 所以规则是：**SCL 低时改数据，SCL 高时读数据**。

## 2.5 ACK 应答机制 ★★
每传输 **8 位（1 字节）后的第 9 个时钟**：
- 接收方把 SDA **拉低** = **ACK**（收到）
- 不拉低 = **NACK**（没收到 / 不再需要）

**三种情况下的 NACK**：
1. 从机地址没匹配上（总线上没有这个从机）→ 主机收到 NACK，知道设备不存在
2. 从机忙 / 无法接收
3. **主机读数据时**：主机不想再读了，用 NACK 告诉从机"够了"

## 2.6 完整的数据帧格式 ★
```
START | 从机地址(7位) + 读写位(1位) | ACK | 数据字节(8位) | ACK | ... | STOP
                                      ↑                    ↑
                                 从机应答              接收方应答
```
读写位：0 = 写（主机→从机），1 = 读（从机→主机）。

## 2.7 速度等级
| 模式 | 速率 | 上拉典型值 |
|---|---|---|
| 标准模式 Standard | 100 kHz | 4.7 kΩ |
| 快速模式 Fast | 400 kHz | 2.2 kΩ |
| Fast-plus | 1 MHz | 1 kΩ 左右 |
| 高速模式 High-speed | 3.4 MHz | 更小 |

## 2.8 进阶考点

### 时钟拉伸（Clock Stretching）★
从机处理不过来时，**主动把 SCL 拉住保持低电平**，让主机等待，直到从机放开 SCL。
**坑**：软件模拟 I2C 经常在这里出错——释放 SCL 后必须**检测 SCL 是否真的变高**（被从机拉着就还没高），否则时序全乱。

### 多主仲裁（Multi-master Arbitration）★
两个主机同时发起传输：
1. 逐位比较 SDA 的实际电平与自己发送的电平
2. **发 1（释放，让上拉拉高）却读到 0（被别人拉低）的主机 → 输掉仲裁 → 立即退出转为接收方**
3. 赢家继续发送，**数据不损坏**（非破坏性仲裁）
→ 与 CAN 的仲裁原理相同（线与 + 显性覆盖隐性）。

### I2C 死锁与恢复
从机在传输中复位/掉电，可能把 SDA 一直拉低 → 总线卡死。
**恢复方法**：主机手动发送 9 个 SCL 时钟脉冲，让从机把剩余数据位移完并释放 SDA，然后发 STOP。

### 10 位地址
前两个字节寻址，兼容 7 位设备（前缀 11110xx 识别）。

## 2.9 考卷怎么问（准备好的答案）

| 问题 | 答题要点 |
|---|---|
| 几根线？各是什么？ | 2 根：SDA 数据、SCL 时钟 |
| 起始/停止条件？ | **画图** + "SCL 高时 SDA 的跳变" |
| 为什么 SDA 在 SCL 高电平时不能变？ | 高电平时的跳变被定义为起始/停止信号 |
| ACK 在第几个时钟？谁拉低？ | 第 9 个时钟，**接收方**拉低 |
| 为什么用开漏 + 上拉？ | 多器件共线不短路 + 线与逻辑（ACK/仲裁的物理基础） |
| 上拉电阻怎么选？ | 速度越快阻值越小（100k→4.7k，400k→2.2k） |
| 和多主冲突怎么办？ | 线与逐位仲裁，发 1 读到 0 的退出 |
| 和 SPI 比？ | 省线、支持多从机、有 ACK；但慢、半双工 |

# 第三部分：SPI

## 3.1 是什么
**Serial Peripheral Interface**，Motorola 提出。四根线：
- **SCLK**：时钟（主机产生）
- **MOSI**（Master Out Slave In）：主出从入
- **MISO**（Master In Slave Out）：主入从出
- **CS/SS**（Chip Select / Slave Select）：片选，**低有效**，**每个从机一根独立 CS**

同步、**全双工**、高速（几十 MHz）。

## 3.2 原理：移位寄存器环 ★★（"为什么读也要发"的答案）
主机和从机各有一个**移位寄存器**（通常 8 位），首尾相连成一个环。
每个时钟脉冲，双方**各移出 1 位、移入 1 位** → 发送和接收**同时进行**。

→ **所以只读不写也必须发 dummy byte（哑数据）**，用哑数据把从机数据"换"出来。

## 3.3 CPOL / CPHA 四种模式 ★★
| 参数 | 含义 |
|---|---|
| **CPOL**（Clock Polarity） | 空闲时 SCLK 是**低**(0) 还是**高**(1) |
| **CPHA**（Clock Phase） | 在**第 1 个**边沿采样(0) 还是**第 2 个**边沿采样(1) |

| 模式 | CPOL | CPHA | 空闲电平 | 采样边沿 |
|---|---|---|---|---|
| **0** | 0 | 0 | 低 | 第 1 个（上升沿） |
| **1** | 0 | 1 | 低 | 第 2 个（下降沿） |
| **2** | 1 | 0 | 高 | 第 1 个（下降沿） |
| **3** | 1 | 1 | 高 | 第 2 个（上升沿） |

**主从必须一致**，否则数据错位（读到全 0 或全 1）。

## 3.4 优缺点（对比 I2C 必答）
| 优点 | 缺点 |
|---|---|
| 快（几十 MHz，远高于 I2C） | 每个从机一根 CS → 引脚占用多 |
| 全双工 | **无 ACK**（不知道从机收到没） |
| 协议开销小（无地址、无应答） | **无标准**（每个器件的命令表/时序都不同） |
| 适合高速数据传输（Flash/屏幕/SD） | 无硬件纠错、无多主 |

## 3.5 调试 SPI 读不到数据怎么查？（场景题）★
1. **CS 是否真被拉低**（示波器/逻辑分析仪看）
2. **CPOL/CPHA 是否与从机手册一致**（模式 0/3 最常见）
3. **先发读 ID 命令验证链路**（如 SPI Flash 的 0x9F 读 JEDEC ID）
4. 时钟频率是否超过从机上限
5. MISO 是否被其他器件占用（多从机时 CS 冲突）
6. 硬件：上拉、走线、电源

# 第四部分：UART

## 4.1 是什么
**Universal Asynchronous Receiver/Transmitter**。**异步**——**没有时钟线**，双方靠约定的波特率各自产生本地时钟。

三根线：**TXD**（发）、**RXD**（收）、**GND**（**必须共地**）。
通信双方 **TX/RX 交叉连接**（我的发接收方的收）。

## 4.2 帧格式 ★★（必须能画）

```
空闲(高电平)
  ‾‾‾‾‾‾‾\___________________________________________________/‾‾‾‾‾‾‾
         |起始| D0 D1 D2 D3 D4 D5 D6 D7 |校验|停止|
         | 0  | ←──── LSB 先发 ────→      |可选| 1   |
```

组成：
- **起始位**：1 位低电平（下降沿让接收方对齐采样时刻）
- **数据位**：5~9 位，通常 **8 位**，**低位先发（LSB first）**
- **校验位**：奇校验 / 偶校验 / 无（可选）
- **停止位**：1 / 1.5 / 2 位高电平

**11 位总长（8N1）** = 1 起始 + 8 数据 + 1 停止 + 1 空闲。

## 4.3 波特率与误差 ★
**波特率**：每秒传输的位数（bps）。常用 9600、115200、921600。

**双方必须一致**；误差超过约 **2~3%** 就会采样错位 → **收到乱码 / 帧错误**（这是最常见的串口故障现象）。

**波特率计算（STM32）**：
```
波特率 = 系统时钟 / (16 × USARTDIV)
例：72MHz / (16 × 115200) ≈ 39.0625
```

## 4.4 RS232 / RS485 / RS422 / TTL ★★（西门子工业场景必考）

| | **TTL** | **RS232** | **RS485** | **RS422** |
|---|---|---|---|---|
| **电平** | 0V / 3.3V(或5V) | **±3~15V**（负逻辑） | **差分**（A/B 两线） | **差分**（4 线） |
| **距离** | 板内 / 短距 | ~15m | **~1200m** | ~1200m |
| **双工** | 全双工 | 全双工 | **半双工** | 全双工 |
| **节点数** | 点对点 | 点对点 | **32+ 多机** | 1 主 10 从 |
| **抗干扰** | 弱 | 中 | **强**（差分+共模抑制） | 强 |
| **典型应用** | MCU 互连、USB 转串口 | 老式工控机、调试口 | **Modbus-RTU 物理层**、PLC | 工业长距全双工 |

**RS485 为什么传得远？** 差分传输：两根线传互补信号，接收端看**差值**，共模干扰被相互抵消；配合双绞线抵消磁场干扰。
**RS232 为什么电平高？** 抗干扰（±12V 摆幅大），但单端、不能多机。

## 4.5 串口通信故障排查（场景题）★
按顺序查：
1. **TX/RX 是否交叉接反**（最常见）
2. **波特率 / 数据位 / 校验位 / 停止位**是否完全一致
3. **是否共地**（不共地电平参考不一致）
4. **电平标准是否匹配**（TTL 直连 RS232 会烧芯片！需 MAX232 转换）
5. 是否需要流控（RTS/CTS）
6. 用逻辑分析仪/示波器看波形与位宽

## 4.6 流控（了解）
- **硬件流控**：RTS/CTS（发送方问"能发吗"）
- **软件流控**：XON/XOFF（特殊字符控制）
- 用途：接收方缓冲区快满时通知发送方暂停，防止丢数据

# 第五部分：CAN（工业/汽车，西门子场景高频）

## 5.1 是什么
**Controller Area Network**，Bosch 为汽车设计。**差分两线** CAN_H / CAN_L，多主广播，为**高噪声、远距离、多节点、高可靠**而生。

**终端电阻**：总线**两端各接 120Ω**（匹配线缆特征阻抗，消除信号反射）。
→ **现场判断总线是否正常：万用表量两端电阻，并联应约 60Ω**。

## 5.2 电平：显性 / 隐性 ★★
| 状态 | 逻辑 | CAN_H | CAN_L | 差压 |
|---|---|---|---|---|
| **隐性**（recessive） | **1** | ≈2.5V | ≈2.5V | ≈0V（总线松弛） |
| **显性**（dominant） | **0** | ≈3.5V | ≈1.5V | ≈2V（总线被驱动） |

**显性覆盖隐性**（线与）→ 这是仲裁的物理基础。

## 5.3 标准数据帧结构 ★★（必须按顺序写）

```
┌─────┬──────────┬─────────┬──────────────┬─────────┬────────┬─────┐
│ SOF │  11位ID  │ 控制段  │  数据 0~8字节 │ CRC 15位│ ACK槽  │ EOF │
│ 1位 │          │(含DLC)  │              │         │  2位   │ 7位 │
└─────┴──────────┴─────────┴──────────────┴─────────┴────────┴─────┘
```

顺序记忆：**起 → ID → 控制 → 数据 → CRC → 应答 → 结束**

**扩展帧**：29 位 ID（IDE 位 = 1），其余类似。

## 5.4 非破坏性仲裁 ★★★（必问）
多节点同时发送时：
1. 每个节点**边发送边回读总线**
2. 发**隐性(1)** 却读到 **显性(0)** 的节点 → 知道冲突了 → **立即退出转接收**
3. 赢家继续发送，**数据零损耗**（不需要重发）

→ **结论：ID 数值越小，优先级越高**（高位先比，先出现 0 的赢）
→ 设计时：紧急报文（刹车）给小 ID，次要报文（车窗）给大 ID。

## 5.5 可靠性机制 ★
| 机制 | 作用 |
|---|---|
| **位填充（Bit Stuffing）** | 连续 5 个相同电平后插入 1 个反相位，保证有跳变沿，让接收方维持时钟同步 |
| **CRC 15 位** | 检错，检出率高 |
| **ACK 槽** | 接收正确的节点在此拉低总线应答 |
| **错误计数器 + bus-off** | 发送/接收错误计数超限 → 节点自动离线，**故障节点不会拖死整条总线** |
| **差分传输** | 抗共模干扰 |

## 5.6 速率
- 经典 CAN：最高 **1 Mbps**（40m 内），长距离要降速
- **CAN FD**：数据段可到 5~8 Mbps，载荷 64 字节
- 常用工业速率：125k / 250k / 500k

## 5.7 位时序（了解）
一个位时间分为：**同步段 SYNC_SEG + 传播段 PROP_SEG + 相位缓冲段1 + 相位缓冲段2**。
采样点通常设置在 **75%~87.5%** 位置。
**全网所有节点的波特率和采样点必须一致**。

## 5.8 CAN 现场调试 ★
1. 量两端 120Ω（并联约 60Ω）
2. 波特率与采样点全网一致
3. 收发器（如 TJA1050）TXD 被拉死为低会占满总线（一直显性）
4. 检查 S 脚（静音/standby）是否误接
5. 用 CAN 分析仪抓报文看错误帧

# 第七部分：题目（30 题，答案已给）

## I2C

### Q1 ★★ I2C 有几根线？各是什么？
**答案**：2 根：**SDA**（Serial Data，数据）、**SCL**（Serial Clock，时钟）。多主多从，靠 7 位（或 10 位）地址区分从机。

### Q2 ★★★ I2C 的起始条件和停止条件分别是什么？
**答案**：
- 起始（START）：**SCL 为高电平时，SDA 由高变低**
- 停止（STOP）：**SCL 为高电平时，SDA 由低变高**
关键：跳变发生在 SCL 高电平期间才被视为控制信号。

### Q3 ★★★ 为什么 I2C 的 SDA 在 SCL 高电平期间必须保持稳定？
**答案**：因为 SCL 高电平期间 SDA 的跳变被定义为起始/停止信号。数据位若在此窗口翻转，接收方会误判为起始或停止，导致帧错位。所以规则是"SCL 低时改数据，SCL 高时读数据"。

### Q4 ★★ I2C 的 ACK 在第几个时钟？谁拉低？读数据时主机发 NACK 表示什么？
**答案**：第 **9** 个时钟，**接收方**把 SDA 拉低表示 ACK。
主机读数据时发 NACK 表示"我不再需要更多数据了"，通知从机结束传输。

### Q5 ★★ I2C 为什么用开漏输出 + 上拉电阻？
**答案**：开漏只能拉低、不能主动输出高电平，高电平靠上拉。
两个好处：① 多器件共线不会短路（都拉低是低电平，安全）② 总线呈**线与逻辑**——任何一方拉低即为低，这是 **ACK 应答**与**多主仲裁**的物理基础。

### Q6 ★ I2C 上拉电阻怎么选？为什么速度越快阻值越小？
**答案**：100kHz 用 4.7kΩ，400kHz 用 2.2kΩ，1MHz 以上更小。
速度越快，总线电容充放电时间常数（RC）必须越小，否则上升沿太缓，高速下采样出错。

### Q7 ★ 两个主机同时发送数据会怎样？
**答案**：逐位仲裁：各主机发一位并回读总线实际电平。发隐性（1，释放总线）却读到显性（0，被别人拉低）的主机输掉仲裁，立即退出转接收；赢家继续，数据不损坏（非破坏性仲裁）。与 CAN 原理相同。

### Q8 什么是时钟拉伸（Clock Stretching）？
**答案**：从机处理不过来时主动把 SCL 拉住保持低电平，让主机等待，直到从机处理完释放 SCL。
坑：软件模拟 I2C 释放 SCL 后必须检测 SCL 是否真的变高（被从机拉着就还没高），否则时序错乱。

### Q9 I2C 总线卡死（SDA 一直低）怎么恢复？
**答案**：某个从机在传输中被复位/掉电，把 SDA 拉住。恢复：主机手动额外发送 **9 个 SCL 时钟脉冲**，让从机把剩余数据位移完并释放 SDA，然后发 STOP 条件复位总线状态。

### Q10 I2C 的一帧完整格式是怎样的？
**答案**：START → 从机地址（7 位）+ 读写位（1 位，0 写 1 读）→ 从机 ACK → 数据字节 + ACK（可多次）→ STOP。

## SPI

### Q11 ★★ SPI 有几根线？各是什么？
**答案**：4 根：**SCLK**（时钟）、**MOSI**（主出从入）、**MISO**（主入从出）、**CS/SS**（片选，低有效，每个从机一根）。

### Q12 ★★★ SPI 为什么只读不写也必须发送数据？
**答案**：SPI 的收发是主机与从机的**移位寄存器首尾相连成环**，每个时钟双方各移出 1 位、移入 1 位。要读从机数据，必须同时发送数据把从机数据"顶"出来 → 所以发 dummy byte（哑数据）。

### Q13 ★★ CPOL 和 CPHA 是什么？一共几种模式？
**答案**：CPOL（时钟极性）决定空闲时 SCLK 为低(0)还是高(1)；CPHA（时钟相位）决定在第 1 个还是第 2 个边沿采样。2×2=**4 种模式**（模式 0/1/2/3），主从必须一致。

### Q14 ★ SPI 和 I2C 的优缺点对比？
**答案**：SPI 优点：速度快（几十 MHz）、全双工、协议开销小；缺点：每个从机一根 CS 占引脚、无 ACK、无统一标准、无多主。
I2C 优点：只要 2 根线、支持多从机（地址寻址）、有 ACK；缺点：慢（100k~3.4M）、半双工、开漏需要上拉。

### Q15 ★ SPI 读不到数据怎么排查？
**答案**：① CS 是否真被拉低 ② CPOL/CPHA 是否与从机手册一致 ③ 先发读 ID 命令（如 Flash 的 0x9F）验证链路 ④ 时钟频率是否超上限 ⑤ MISO 是否被其他从机抢占 ⑥ 硬件（上拉、走线、电源）。

## UART

### Q16 ★★ UART 一帧的组成是什么？
**答案**：起始位（1 位低电平）+ 数据位（5~9 位，**LSB 先发**）+ 可选校验位 + 停止位（1/1.5/2 位高电平）。空闲时为高电平。

### Q17 ★★ UART 波特率不一致会怎样？为什么？
**答案**：收到**乱码 / 帧错误**。
原因：UART 异步无时钟线，靠起始位对齐后按波特率推算每个位的采样时刻；波特率差超过约 2~3% 后累积误差使采样点偏移到位的边沿甚至隔壁位，数据就错了。

### Q18 ★ RS232、RS485、RS422 的区别？
**答案**：
- RS232：单端 ±3~15V，全双工，点对点，~15m
- RS485：**差分** A/B 两线，**半双工**，可挂 32+ 节点，~1200m，抗共模干扰强，Modbus-RTU 物理层
- RS422：**差分 4 线**，全双工，1 主 10 从，~1200m
RS485/422 传得远的原因：差分传输看差值，共模干扰互相抵消。

### Q19 ★ TTL 串口能直接接 RS232 吗？
**答案**：**不能**。TTL 是 0/3.3V（或 5V）单端，RS232 是 ±3~15V 负逻辑，直连会损坏芯片。必须用电平转换芯片（如 MAX232）。

### Q20 串口通信故障怎么排查？
**答案**：① TX/RX 是否交叉接反 ② 波特率/数据位/校验位/停止位是否一致 ③ 是否共地 ④ 电平标准是否匹配 ⑤ 是否需要流控 ⑥ 用示波器/逻辑分析仪看波形与位宽。

## CAN

### Q21 ★★ CAN 采用什么电气方式？为什么？
**答案**：**差分两线**（CAN_H / CAN_L）。优点：抗共模干扰能力强（看差值）、适合高噪声工业/汽车环境、可远距离。总线两端各接 120Ω 终端电阻匹配阻抗、消除反射。

### Q22 ★★★ CAN 为什么 ID 越小优先级越高？
**答案**：CAN 用**线与仲裁**：显性(0) 覆盖隐性(1)。多节点同时发送时逐位比较，先发出 0 的节点把总线拉低，发 1 的节点回读到 0 就知道自己输了并退出。ID 数值越小，高位越早出现 0，越早赢得仲裁。

### Q23 ★★ CAN 标准数据帧的结构顺序？
**答案**：帧起始 SOF → 11 位 ID（+RTR/IDE）→ 控制段（含 DLC）→ 数据段 0~8 字节 → CRC 15 位 → ACK 槽 → 帧结束 EOF 7 位。

### Q24 ★ 什么是位填充（Bit Stuffing）？为什么要填充？
**答案**：发送方在连续出现 **5 个相同电平**后自动插入 1 个反相位位。目的：保证总线上有足够的跳变沿，让接收方维持时钟同步（CAN 是异步总线，靠边沿同步）。

### Q25 ★ CAN 的可靠性机制有哪些？
**答案**：① CRC 15 位检错 ② ACK 槽应答 ③ 位填充保证同步 ④ 错误计数器 + bus-off（故障节点自动离线，不拖死总线）⑤ 差分传输抗干扰。

### Q26 ★ 现场怎么判断 CAN 总线是否正常？
**答案**：断电后用万用表量 CAN_H 与 CAN_L 之间的电阻，两端各 120Ω 并联应约 **60Ω**；若为 120Ω 说明只有一端接了终端电阻，0Ω 或无穷大说明短路/断路。

### Q27 CAN 现场通信不正常怎么排查？
**答案**：① 量终端电阻（约 60Ω）② 波特率与采样点是否全网一致 ③ 收发器 TXD 是否被拉死为低（会占满总线为显性）④ S 脚（静音）是否误接 ⑤ 用分析仪看错误帧类型（位错误/格式错误/ACK 错误）。

## 综合对比

### Q28 ★★ 请对比 UART、I2C、SPI、CAN 四种总线。
**答案**：见第一部分表格。要点：线数（3/2/4/2 差分）、同步性（异步/同步/同步/同步）、双工（全/半/全/半）、寻址（无/地址/片选/ID）、速度（低/中/高/中）、应答（无/ACK/无/ACK+CRC）、距离（短/板内/板内/远）。

### Q29 ★ 一个系统要接 8 个传感器 + 1 片 Flash + 1 路远距离通信，怎么选总线？
**答案**：
- 8 个传感器：**I2C**（省引脚，地址寻址，传感器常用 I2C）
- Flash：**SPI**（速度要求高）
- 远距离：**CAN** 或 **RS485**（差分抗干扰、可远距）
说明理由即可得过程分。

### Q30 如果 I2C 总线上挂了两个地址相同的器件会怎样？
**答案**：会冲突。两设备同时应答同一地址 → ACK 阶段同时拉低 SDA（线与，不会短路），但读取数据时两者都驱动 SDA → 数据错乱（一个想拉高、一个拉低时，线与结果是低）。
解决：选地址可配置的器件、用 I2C 多路复用器（TCA9548 类）、或改用 SPI。
