# 第一部分：考点（28 条）

## 一、进程与线程

### 1.1 进程 vs 线程 ★★
| 维度 | 进程 | 线程 |
|---|---|---|
| 定义 | **资源分配**的基本单位 | **CPU 调度**的基本单位 |
| 地址空间 | 独立（独立页表） | 共享进程的地址空间 |
| 资源开销 | 大（切换要换页表、刷 TLB） | 小（共享地址空间） |
| 通信 | IPC（管道/消息队列/共享内存/socket/信号） | 直接读写共享变量（需同步） |
| 隔离性 | 强（一个崩溃不影响其他） | 弱（一个崩溃整个进程挂） |

**内核角度**：Linux 中进程和线程都是 `task_struct`，区别在于 `clone()` 时传的标志位——是否共享地址空间（CLONE_VM）、文件表（CLONE_FILES）、信号处理（CLONE_SIGHAND）。
**内存角度**：进程有独立虚拟地址空间；线程共享代码段/数据段/堆/全局变量，各自独享**栈**和寄存器。

### 1.2 进程状态 ★
```
new → ready ⇄ running → terminated
              ↓ ↑
            waiting（阻塞）
```
- **就绪**：除 CPU 外一切就绪
- **运行**：占用 CPU（单核同一时刻只有一个）
- **阻塞/等待**：等事件（IO 完成、信号量），即使 CPU 空闲也不能运行
- 补充：**僵尸进程**（已终止但父进程未回收，占 PID）、**孤儿进程**（父进程先死，被 init/systemd 收养）

### 1.3 fork ★★
```c
pid_t pid = fork();
if (pid == 0) { /* 子进程 */ }
else if (pid > 0) { /* 父进程，pid 是子进程 PID */ }
else { /* 失败 */ }
```
**返回值**：父进程得到子 PID，子进程得到 0，失败 -1。
**共享/不共享**：共享文件描述符（同一文件偏移）、共享部分只读页；不共享内存数据、PID、信号处理设置。
**写时复制 COW**：fork 后父子共享物理页且标为只读，任一方写入触发缺页异常，内核才复制该页 → 避免无谓的全量拷贝。

### 1.4 exec 与 fork 组合
`fork()` 创建子进程 → 子进程 `exec()` 加载新程序（替换整个地址空间）→ 这是 shell 执行命令的经典模式。

### 1.5 进程间通信 IPC ★★
| 方式 | 特点 | 场景 |
|---|---|---|
| **管道 pipe** | 半双工、仅血缘进程、字节流、内核缓冲 | `ls \| grep` |
| **命名管道 FIFO** | 有文件名，无血缘也能通信 | 不相关进程 |
| **消息队列** | 有消息边界、可带类型、内核维护 | 结构化消息 |
| **共享内存** | **最快**（无内核拷贝） | 大数据量 |
| **信号量** | 用于**同步**，不传数据 | 配共享内存 |
| **信号 signal** | 异步通知，信息量少 | kill、SIGCHLD |
| **socket** | 可跨主机 | 网络 |

**共享内存为什么最快**：数据直接映射到两进程地址空间，读写不经过内核；其他 IPC 都要 `copy_to_user`/`copy_from_user` 拷贝。劣势：需自己加同步机制。

### 1.6 线程同步方式 ★★
| 机制 | 说明 | 场景 |
|---|---|---|
| **互斥锁 mutex** | 同一时刻一个线程持有，有所有权 | 保护临界区 |
| **信号量 semaphore** | 计数，可控制并发数 | 资源计数、生产者消费者 |
| **条件变量** | 等待条件成立，配合互斥锁 | 避免忙等 |
| **读写锁** | 读共享、写独占 | 读多写少 |
| **自旋锁** | 忙等，不睡眠 | 临界区极短、中断上下文 |
| **原子操作** | CPU 指令保证（CAS） | 无锁编程、计数器 |

### 1.7 死锁 ★★
**四个必要条件**：
1. **互斥**：资源不能共享
2. **持有并等待**：拿着一个等另一个
3. **不可剥夺**：不能强行抢占
4. **循环等待**：A 等 B、B 等 A

**处理策略**：
- **预防**（破坏条件）：一次性申请全部资源、按全局顺序申请（破循环等待）、允许超时放弃（破不可剥夺）
- **避免**：银行家算法（需预知最大需求，实际少用）
- **检测与恢复**：资源分配图找环
- **工程实践**：统一加锁顺序 + 带超时获取

### 1.8 生产者-消费者问题 ★
标准解法：互斥锁（保护缓冲区）+ 两个信号量（empty 计数、full 计数）。
```c
sem_t empty = N, full = 0;
mutex_t mtx;

// 生产者
sem_wait(&empty);            // 有空格子？没有就等
lock(&mtx);
put_item();
unlock(&mtx);
sem_post(&full);             // 通知有货了

// 消费者
sem_wait(&full);             // 有货？没有就等
lock(&mtx);
get_item();
unlock(&mtx);
sem_post(&empty);            // 通知有空格了
```
**考点**：为什么需要互斥锁——信号量只保证"数量"正确，多个生产者同时写缓冲区仍需互斥。

### 1.9 读者-写者问题（概念）
允许多个读者同时读；写者独占。变体：读优先/写优先/公平。
实现：计数器记录读者数（第一个读者加锁，最后一个解锁）+ 写锁。

### 1.10 线程池（为什么需要，怎么实现）★★
**为什么需要**：频繁创建/销毁线程开销大（每次要分配栈、初始化）。线程池预先创建一批线程，复用它们处理任务。

**结构**：
```
任务队列（线程安全队列）
     ↑ 生产者提交任务
[worker1][worker2][worker3]...  ← 消费者，循环从队列取任务执行
```

**实现要点**：
1. 预先创建 N 个 worker 线程
2. 一个**线程安全的任务队列**（互斥锁 + 条件变量）
3. worker 循环：`取任务 → 执行 → 再取`；队列空则阻塞在条件变量上
4. 提交任务：加锁 → 入队 → 唤醒一个 worker
5. 销毁：置退出标志 → 唤醒所有 worker → join

**线程数怎么定**：
- **CPU 密集型**：线程数 ≈ CPU 核数（或核数+1）
- **IO 密集型**：线程数可以更多（等待 IO 时其他线程能干活）
- 嵌入式：通常固定少量线程，用静态分配

**优点**：避免频繁创建销毁、控制并发数、任务排队削峰。
**缺点**：实现复杂、任务队列也是共享资源（要同步）、线程数配错会浪费或阻塞。

### 1.11 守护进程（Daemon）★★
**定义**：在后台长期运行、与终端脱离的进程（如 sshd、nginx）。

**创建步骤（5 步，面试常问）**：
```c
pid_t pid = fork();
if (pid > 0) exit(0);          /* 1. fork 后父进程退出，子进程被 init 收养 */
setsid();                       /* 2. 创建新会话，脱离控制终端 */
pid = fork();
if (pid > 0) exit(0);           /* 3. 再 fork 一次，确保不是会话首进程（防止重新获取终端） */
chdir("/");                     /* 4. 改变工作目录，避免占用可卸载的文件系统 */
umask(0);                       /* 5. 清除文件权限掩码 */
/* 之后关闭/重定向标准输入输出到 /dev/null */
close(STDIN_FILENO); close(STDOUT_FILENO); close(STDERR_FILENO);
open("/dev/null", O_RDWR); dup2(0, STDOUT_FILENO); dup2(0, STDERR_FILENO);
```
**为什么要 fork 两次**：第一次 fork + setsid 脱离终端；第二次 fork 确保进程**不是会话首进程**，从而无法再申请控制终端。

**现代做法**：systemd 管理（写 .service 文件，`Type=forking` 或 `simple`），不需要自己写守护化代码。

### 1.12 信号（Signal）★★
**定义**：软件中断，用于异步通知进程某事件发生。

**常用信号**：
| 信号 | 编号 | 含义 | 默认动作 |
|---|---|---|---|
| **SIGINT** | 2 | Ctrl+C | 终止 |
| **SIGTERM** | 15 | `kill` 默认 | **终止**（可捕获，优雅退出） |
| **SIGKILL** | 9 | 强杀 | **终止且不可捕获/忽略** |
| SIGSEGV | 11 | 段错误 | 终止 + core |
| SIGCHLD | 17 | **子进程状态变化** | 忽略 |
| SIGPIPE | 13 | 写已关闭的管道/socket | 终止 |
| SIGALRM | 14 | 定时器超时 | 终止 |
| SIGHUP | 1 | 终端挂断 | 终止 |

**`kill -9` 和 `kill -15` 的区别**（高频）：`-15`（SIGTERM）可被捕获，程序可以做清理后优雅退出；`-9`（SIGKILL）由内核直接终止，不可捕获、不可忽略，进程无法做任何清理。

**注册处理函数**：
```c
void handler(int sig) { /* 只能调用 async-signal-safe 函数（write 可以，printf 不行） */ }
signal(SIGINT, handler);                    /* 简单版 */
struct sigaction sa = {0};
sa.sa_handler = handler;
sigemptyset(&sa.sa_mask);
sigaction(SIGINT, &sa, NULL);               /* 推荐版，功能更全 */
```

**考点**：
- 信号处理函数里只能调 `async-signal-safe` 的函数（不能 printf、malloc）
- 用 `sigprocmask` 可以阻塞信号
- 信号不排队（同种信号多次到达只处理一次）

## 二、调度

### 2.1 进程调度算法 ★
| 算法 | 特点 | 缺点 |
|---|---|---|
| **FCFS** 先来先服务 | 简单 | 长作业拖累短作业（护航效应） |
| **SJF** 短作业优先 | 平均等待时间最短 | 需预知运行时间，长作业饿死 |
| **RR** 时间片轮转 | 公平、响应快 | 时间片大小的选择；上下文切换开销 |
| **优先级调度** | 重要任务优先 | 低优先级饿死（可用老化解决） |
| **多级反馈队列** | 综合最优，UNIX/Linux 传统 | 实现复杂 |

**评价指标**：CPU 利用率、吞吐量、周转时间（完成-提交）、等待时间、响应时间。

### 2.2 Linux 的 CFS（了解）
完全公平调度：用虚拟运行时间 `vruntime` 作为红黑树键，总是调度 vruntime 最小的任务；nice 值影响权重。实时任务用 FIFO/RR 调度类，优先级更高。

## 三、内存管理

### 3.1 虚拟内存 ★★
**作用**：
1. **进程隔离**：各进程有独立地址空间，无法互访
2. **可超过物理内存**：不常用页换到磁盘（swap）
3. **共享**：共享库只读映射一份
4. **按需加载**：只调入实际访问的页
5. **保护**：页级读/写/执行权限

**实现**：MMU（内存管理单元）把虚拟地址翻译成物理地址，靠**页表**。

### 3.2 分页 / 分段 ★
| | 分页 | 分段 |
|---|---|---|
| 大小 | **固定**（通常 4KB） | **不固定**（逻辑意义，如代码段/数据段） |
| 目的 | 提高内存利用率、消除外部碎片 | 满足逻辑结构、便于共享保护 |
| 碎片 | 内部碎片（页内） | 外部碎片 |
| 地址 | 页号 + 页内偏移 | 段号 + 段内偏移 |

**段页式**：先分段再分页（x86 早期做法）。

### 3.3 页表 / TLB / 多级页表 ★
- **页表**：虚拟页号 → 物理页框号
- **多级页表**（x86-64 四级）：只保存实际用到的页表项，节省空间（时间换空间）
- **TLB**（Translation Lookaside Buffer）：页表的高速缓存（在 MMU 内部），命中则无需访存查页表
  - 进程切换要刷新 TLB（或用 ASID 标签区分）
- **页表项还含权限位**：读/写/执行/用户态可访问、脏位、访问位

### 3.4 缺页中断 ★★
**流程**：
1. CPU 访问虚拟地址 → MMU 查页表发现页不在内存（有效位=0）
2. 触发**缺页异常**（Page Fault）
3. 内核：若有空闲页框直接分配；否则按置换算法选一个牺牲页，脏页先写回磁盘
4. 从磁盘（或文件）读入所需页
5. 更新页表、刷新 TLB
6. 返回用户态，**重新执行**触发缺页的那条指令

**考点**：缺页中断是"中断"还是"异常"？是**异常**（同步，由当前指令引起），不是外部中断。

### 3.5 页面置换算法 ★
| 算法 | 规则 | 特点 |
|---|---|---|
| **OPT** 最优 | 淘汰未来最久不用的 | 理论最优，无法实现（需预知未来），作为基准 |
| **FIFO** | 淘汰最早进入的 | 简单；有 Belady 异常（页框增多反而缺页更多） |
| **LRU** 最近最久未用 | 淘汰最久未访问的 | 效果好，实现需记录访问时间（开销大） |
| **Clock**（近似 LRU） | 环形链表 + 访问位，访问位为 1 则清零并跳过 | 实际常用，开销小 |
| **LFU** 最少使用 | 淘汰访问次数最少的 | 需计数；对突发访问不友好 |

### 3.6 malloc 的实现（内核向）★
用户态 malloc 不是直接系统调用：
1. **小块内存**（< 128KB）：从 `brk`/`sbrk` 维护的堆区分配，用**空闲链表**管理（首次适配/最佳适配/分离适配）
2. **大块内存**（≥ 128KB）：用 `mmap` 直接映射（`MAP_ANONYMOUS`），free 时 munmap
3. 分配块头部存大小信息，便于 free 时判断和合并相邻空闲块

**内核态分配**：`kmalloc`（slab 缓存，小对象）、`vmalloc`（大块、虚拟连续）、`kmem_cache`（专用缓存）。

### 3.7 内存碎片
- **内部碎片**：分配给进程的内存比实际需要的大（分页/固定块）
- **外部碎片**：空闲内存总量够但分散，无法满足大块请求（分段/动态分配）
- 解决：分页消除外部碎片；slab/内存池预分配固定块

### 3.8 内存映射 mmap（了解）
把文件或匿名内存映射到进程地址空间 → 读写内存即读写文件，省去 read/write 拷贝（**零拷贝**的一种）。

## 四、文件系统

### 4.1 VFS 与 inode ★★（你的强项）
**VFS 四个核心对象**：
| 对象 | 含义 |
|---|---|
| **superblock** | 整个文件系统的元信息（类型、块大小、inode 数） |
| **inode** | 单个文件的元数据（权限、大小、时间、数据块指针），**不含文件名** |
| **dentry** | 目录项，文件名 → inode 的映射（有缓存） |
| **file** | 打开的文件实例（含读写位置、打开模式） |

**inode 里有什么**：文件类型、权限、owner、size、时间戳（atime/mtime/ctime）、链接数、数据块指针（直接块 + 间接块，ext4 用 extent 树）。
**inode 里没什么**：**文件名**（在 dentry 里）、文件内容（在数据块里）。

### 4.2 硬链接 vs 软链接 ★
| | 硬链接 | 软链接（符号链接） |
|---|---|---|
| 本质 | 另一个文件名指向**同一 inode** | 独立文件，内容是**目标路径** |
| inode | 相同 | 不同 |
| 链接计数 | 加 1 | 不加 |
| 跨分区 | **不能** | 能 |
| 指向目录 | 不能（普通用户） | 能 |
| 目标删除后 | 仍可访问（inode 还在） | **失效**（悬空） |

### 4.3 日志文件系统与掉电保护 ★★（你的实战强项）
**为什么需要日志**：掉电时若只写了部分元数据，文件系统会不一致（如 inode 指向已释放的块）。
**journaling 三种模式**：
1. **data=journal**：数据和元数据都写日志（最安全，最慢）
2. **data=ordered**（默认）：元数据写日志，数据先落盘再提交元数据
3. **data=writeback**：只记录元数据（最快，可能数据不一致）

**其他掉电保护手段**：
- **写时复制 COW**（btrfs/zfs）：新数据写到新位置，最后原子更新指针
- **barrier / flush**：确保写顺序落盘（SSD/Flash 的 cache 要 flush）
- **电池/超级电容后备**：掉电后靠电容供电完成最后写入
- **Flash 层面**：坏块管理、ECC、磨损均衡、页级校验

### 4.4 文件系统的层次（你的内核背景）
```
用户态 (open/read/write)
  ↓ 系统调用
VFS（统一抽象）
  ↓
具体文件系统（ext4 / f2fs / FAT / 自研）
  ↓
块设备层（bio、调度器）
  ↓
MTD / 块驱动（NAND / eMMC / SD）
  ↓
硬件（Flash 控制器）
```

### 4.5 NAND Flash 特性（结合你的项目）★
- 按**页**读写（如 2KB/页），按**块**擦除（如 128 页/块）
- **必须先擦后写**；写入前该页必须是擦除状态（0xFF）
- **坏块**：出厂坏块 + 使用中新增，必须做坏块管理
- **磨损均衡**：每块擦写次数有限（SLC ~10万次，TLC ~1千次）
- **ECC**：需要校验纠错（BCH/LDPC）
- **掉电风险**：写页过程中掉电 → 该页数据损坏 → 需要页级校验与恢复策略

## 五、IO 模型

### 5.1 五种 IO 模型 ★
| 模型 | 特点 |
|---|---|
| **阻塞 IO** | read 一直等数据就绪 |
| **非阻塞 IO** | read 立即返回（没数据返回 EAGAIN），需轮询 |
| **IO 多路复用**（select/poll/epoll） | 一个线程监控多个 fd |
| **信号驱动 IO** | 数据就绪时发 SIGIO |
| **异步 IO**（AIO/io_uring） | 内核完成整个读写后通知 |

### 5.2 select / poll / epoll ★
（同一张表在 `23-网络协议.md` 5.2 用于网络编程视角，此处从 IO 模型角度说明）

| | select | poll | epoll |
|---|---|---|---|
| fd 上限 | 1024（FD_SETSIZE） | 无上限 | 无上限 |
| 数据结构 | 位图 | 数组 | 红黑树 + 就绪链表 |
| 每次调用 | 需拷贝全部 fd 到内核 + O(n) 遍历 | 同 select | **只拷贝一次**，事件驱动 |
| 复杂度 | O(n) | O(n) | **O(1)**（就绪 fd 数） |
| 触发方式 | 水平触发 | 水平触发 | 水平(LT)/边缘(ET) |
| 场景 | 少量连接 | 少量连接 | **大量连接（高并发）** |

### 5.3 零拷贝
- `mmap + write`：映射文件到内存，省一次拷贝
- `sendfile`：内核态直接把文件数据送到 socket，不经用户态
- `splice`：管道式零拷贝
**价值**：减少 CPU 拷贝次数和上下文切换。

## 六、中断与内核机制（你的强项）

### 6.1 中断上半部/下半部 ★★
| | 上半部（硬中断） | 下半部 |
|---|---|---|
| 特点 | 屏蔽中断、必须极短 | 可被打断、可较慢 |
| 做什么 | 清中断标志、读硬件数据、发信号 | 数据处理、协议解析、唤醒任务 |
| 形式 | 中断处理函数 | softirq / tasklet / workqueue |

**三种下半部**：
- **softirq**：内核静态分配（10 种），同类型可并发（需自己保证安全），用于网络/块设备
- **tasklet**：基于 softirq，**同类型串行**执行，简单安全
- **workqueue**：跑在**内核线程**里，**可以睡眠**，适合耗时/阻塞操作

**选择**：需要睡眠/阻塞 → workqueue；纯 CPU 密集且短 → tasklet/softirq。

### 6.2 中断处理为什么不能太长 ★
- 屏蔽同级/低优先级中断，增加响应延迟，可能丢中断
- 中断上下文不能睡眠（不能调用可能阻塞的函数）
- 影响系统整体实时性

### 6.3 用户态与内核态 ★
| | 用户态 | 内核态 |
|---|---|---|
| 权限 | 受限（x86 ring3） | 全部（ring0） |
| 可访问 | 自己的地址空间 | 全部内存、硬件 |
| 切换方式 | **系统调用**、中断、异常 |

**系统调用过程**：
1. 用户态把参数放入约定寄存器，执行 `syscall`/`int 0x80`
2. CPU 切换到内核态，跳转到系统调用入口
3. 内核根据调用号查表执行对应服务
4. 返回用户态并恢复上下文

### 6.4 上下文切换开销 ★
**进程切换**：保存/恢复寄存器 + 切换页表 + **刷 TLB** + cache 变冷（最贵）
**线程切换**：保存/恢复寄存器 + 栈切换，不换页表（便宜）
**中断上下文切换**：保存/恢复寄存器（最便宜）

### 6.5 内存屏障（了解）
- 编译器屏障：`barrier()`、`asm volatile("" ::: "memory")`
- CPU 屏障：`mb()`、`rmb()`、`wmb()`
- 用途：保证指令顺序，防止 CPU/编译器乱序导致多核可见性问题

# 第二部分：题目（30 题，答案已给）

### Q1 ★★ 进程和线程的区别？（内核角度 + 内存角度）
**答案**：内核角度：都是 task_struct，区别在 clone 时是否共享地址空间/文件表/信号处理。内存角度：进程有独立地址空间（独立页表）；线程共享代码段/数据段/堆，各自独享栈和寄存器。调度角度：线程是 CPU 调度单位，进程是资源分配单位。

### Q2 ★ 进程有哪几种状态？
**答案**：创建、就绪（除 CPU 外一切就绪）、运行、阻塞/等待（等事件）、终止。
补充：僵尸进程（终止但父未回收）、孤儿进程（父先死被 init 收养）。

### Q3 ★★ fork 后父子进程共享什么？COW 是什么？
**答案**：共享文件描述符（同一偏移）、部分只读代码页；不共享内存数据、PID。
COW：fork 后父子共享物理页并标记只读，任一方写入触发缺页异常，内核才复制该页，避免全量拷贝。
fork 返回值：父得子 PID，子得 0。

### Q4 僵尸进程是什么？怎么避免？
**答案**：子进程已终止，但父进程没有调用 wait/waitpid 回收其退出状态 → 进程表项残留（占 PID）。
避免：父进程及时 wait；用信号 SIGCHLD 处理；或父进程忽略 SIGCHLD（子进程自动回收）；让 init 收养（父先死）。

### Q5 ★★ 进程间通信有哪些方式？共享内存为什么最快？
**答案**：管道、命名管道、消息队列、共享内存、信号量、信号、socket。
共享内存最快：数据直接映射到两进程地址空间，读写不经内核；其他 IPC 需要内核拷贝（copy_to/from_user）。劣势：需自己加同步。

### Q6 ★★ 线程同步有哪些方式？
**答案**：互斥锁（保护临界区，有所有权）、信号量（计数，控制并发数）、条件变量（等待条件，配合互斥锁）、读写锁（读共享写独占）、自旋锁（忙等，临界区极短或中断上下文）、原子操作（CAS，无锁）。

### Q7 ★★ 死锁的四个必要条件？如何避免？
**答案**：互斥、持有并等待、不可剥夺、循环等待。
避免：破坏任一条件——一次性申请全部资源（破持有等待）、按全局顺序申请（破循环等待）、超时放弃（破不可剥夺）。工程实践：统一加锁顺序 + 超时。

### Q8 ★ 写一个生产者-消费者模型，说明为什么需要互斥锁。
**答案**：见 1.8。信号量 empty/full 只保证"格子数量"正确；多个生产者同时写同一缓冲区时仍需互斥锁保护，否则数据竞争。顺序：先等资源（信号量）再拿锁——反过来会死锁。

### Q9 ★ 进程调度算法有哪些？各自优缺点？
**答案**：FCFS（简单，长作业拖累短作业）、SJF（平均等待最短，需预知时间且长作业饿死）、RR（公平响应快，时间片选择与切换开销）、优先级（重要优先，低优先级饿死，用老化解决）、多级反馈队列（综合最优，实现复杂）。

### Q10 ★★ 虚拟内存的作用？缺页中断流程？
**答案**：作用：进程隔离、可超物理内存、共享库、按需加载、内存保护。
流程：访问虚拟地址 → MMU 查页表发现不在内存 → 触发缺页异常 → 内核分配页框（满了则按置换算法淘汰一个，脏页写回） → 从磁盘读入 → 更新页表、刷 TLB → 返回重新执行该指令。
注意：缺页是**异常**（同步），不是外部中断。

### Q11 ★ TLB 是什么？进程切换为什么要处理它？
**答案**：TLB = 页表的高速缓存（MMU 内），命中无需访存查页表。
进程切换后页表变了，TLB 里旧映射失效 → 必须刷新（或使用 ASID 标签区分不同进程，只刷新必要的项）。这是进程切换开销大的主要原因之一。

### Q12 ★ 分页和分段的区别？
**答案**：分页大小固定（4KB）、目的是提高内存利用率消除外部碎片、有内部碎片；分段大小不固定、有逻辑意义（代码段/数据段）、有外部碎片、便于共享保护。地址结构：页=页号+偏移，段=段号+偏移。段页式结合两者。

### Q13 ★ 页面置换算法有哪些？LRU 和 FIFO 的区别？
**答案**：OPT（理论最优，不可实现，作基准）、FIFO（淘汰最早进入的，有 Belady 异常）、LRU（淘汰最久未访问的，效果好但开销大）、Clock（近似 LRU，环形+访问位，实际常用）、LFU（淘汰访问次数最少的）。
LRU vs FIFO：LRU 考虑访问历史，FIFO 只看进入时间；FIFO 在页框增多时可能缺页反而增加（Belady 异常），LRU 不会。

### Q14 ★ 多级页表解决什么问题？TLB 解决什么问题？
**答案**：多级页表解决"页表本身占用内存过大"（只保存实际使用的部分，时间换空间）；TLB 解决"多级页表导致地址翻译要多次访存"（用缓存加速，命中则一次搞定）。

### Q15 ★★ inode 里有什么？没有什么？为什么一个文件可以有多个文件名？
**答案**：inode 存元数据（类型、权限、owner、size、时间戳、链接数、数据块指针）。**不含文件名**（文件名在目录项 dentry 里）。
多个文件名对应同一 inode 就是硬链接——目录项不同但指向同一个 inode，链接计数加一。

### Q16 ★ 硬链接和软链接的区别？
**答案**：硬链接指向同一 inode（inode 相同、链接计数+1、不能跨分区、不能指向目录、目标删除仍可访问）；软链接是独立文件存目标路径（inode 不同、可跨分区、可指目录、目标删除后失效）。

### Q17 ★ 文件系统掉电如何保证不丢数据？
**答案**：① **日志（journaling）**：先把元数据变更写日志，再改实际数据，掉电后重放/回滚；默认 data=ordered 模式保证数据先落盘 ② **写时复制 COW**：新数据写新位置，最后原子更新指针 ③ **barrier/flush**：保证写顺序真正落盘 ④ **电容/电池后备**：掉电后完成最后写入 ⑤ Flash 层：坏块管理、ECC、页级校验。

### Q18 ★ NAND Flash 有什么特性？对这些特性怎么应对？
**答案**：按页读写、按块擦除、必须先擦后写、有坏块、擦写寿命有限、写过程中掉电会损坏该页。
应对：坏块管理（坏块表）、**磨损均衡**（动态/静态）、ECC 校验纠错、页级备份与恢复、垃圾回收（GC）、预留空间（over-provisioning）。

### Q19 ★ 五种 IO 模型？epoll 比 select 好在哪？
**答案**：阻塞、非阻塞、IO 多路复用、信号驱动、异步 IO。
epoll 优势：① 无 fd 数量上限（select 1024）② 只用拷贝一次 fd（select 每次调用都拷贝）③ 事件驱动，只返回就绪的 fd，复杂度 O(1) 而非 O(n) ④ 支持边缘触发（ET）。

### Q20 IO 多路复用的水平触发和边缘触发区别？
**答案**：水平触发（LT）：只要缓冲区有数据就一直通知，直到读完——编程简单，不易漏数据。边缘触发（ET）：只在状态变化时通知一次，必须一次读完（循环读到 EAGAIN）——效率高但容易漏数据。

### Q21 ★★ 中断上半部和下半部？三种下半部怎么选？
**答案**：上半部：屏蔽中断、必须极短，只清标志/读数据/发信号。下半部：可被打断、做耗时处理。
- softirq：静态分配，同类型可并发，用于网络/块设备
- tasklet：基于 softirq，同类型串行，简单安全
- workqueue：内核线程中执行，**可以睡眠**，适合耗时/阻塞操作
选择：需要睡眠 → workqueue；短且纯 CPU → tasklet。

### Q22 ★ 中断为什么不能太长？中断里不能做什么？
**答案**：会屏蔽同级/低优先级中断，增大响应延迟，可能丢中断，破坏实时性。
不能做：睡眠/阻塞、malloc（可能睡眠）、拿可能阻塞的锁、耗时计算、调用不可重入函数（printf）、浮点运算（若不保存 FPU 上下文）。

### Q23 ★ 用户态和内核态怎么切换？
**答案**：三种方式——**系统调用**（主动）、**中断**（外部事件）、**异常**（如缺页、除零）。
过程：CPU 保存现场 → 切换到内核栈 → 按特权级进入内核代码 → 处理 → 恢复现场返回用户态。

### Q24 进程切换为什么比线程切换慢？
**答案**：进程切换要：保存/恢复全部寄存器 + **切换页表**（CR3）+ **刷新 TLB**（缓存失效）+ cache 变冷。线程切换只保存/恢复寄存器 + 换栈，不换页表、不刷 TLB。所以进程切换开销明显更大。

### Q25 ★ malloc 是怎么实现的？为什么大块内存走 mmap？
**答案**：小块（<128KB）从 brk 维护的堆区分配，用空闲链表管理；大块（≥128KB）用 mmap 直接匿名映射，free 时 munmap 归还。
大块走 mmap 的原因：避免在堆里留下大空洞（外部碎片），且可以直接归还给系统。

### Q26 什么是内部碎片和外部碎片？
**答案**：内部碎片 = 分配给进程的内存比实际用的大（分页/固定块分配）；外部碎片 = 空闲内存总量够但分散成不连续小块，无法满足大块请求（分段/动态分配）。分页消除外部碎片但有内部碎片；内存池/固定块也是内部碎片换无外部碎片。

### Q27 ★ 系统调用是什么？为什么需要它？
**答案**：系统调用是用户程序请求内核服务的唯一入口（文件、进程、内存、设备管理等）。
需要它的原因：用户态权限受限，不能直接操作硬件/内核数据结构；通过系统调用让内核代为执行，保证安全与抽象。

### Q28 内核态分配内存有哪些方式？
**答案**：`kmalloc`（连续物理内存，用于小对象，基于 slab）、`vmalloc`（虚拟连续、物理可不连续，用于大块）、`kmem_cache`（专用对象缓存，如 task_struct）、`alloc_pages`（页级，buddy 算法）。

### Q29 ★ 什么是写时复制（COW）？除了 fork 还有哪些应用？
**答案**：多个使用者共享同一份数据并标记只读，任一方写入时才复制一份。
应用：fork（父子共享页）、文件系统（btrfs/zfs 的 COW 保证一致性）、Docker 镜像分层、内存去重（KSM）。

### Q30 ★ 一个程序从磁盘到开始运行，经历了什么？
**答案**：① shell 调 fork 创建子进程 ② 子进程 execve 加载可执行文件（校验 ELF 头、映射代码段/数据段、设置入口）③ 内核加载动态链接器、完成符号重定位 ④ 创建栈、传入 argc/argv、envp ⑤ 跳转到入口（_start）→ 初始化 libc → 调用 main。
**嵌入式版本**：BootROM → bootloader（校验+跳转）→ 应用固件（启动代码拷贝 .data、清 .bss、设向量表）→ main。

### Q31 ★ 什么是线程池？为什么需要它？线程数怎么定？
**答案**：预先创建一批 worker 线程，从共享任务队列取任务执行，避免频繁创建销毁线程的开销。
结构：任务队列（互斥锁+条件变量）+ N 个 worker 循环取任务。
线程数：CPU 密集型 ≈ CPU 核数；IO 密集型可更多（等 IO 时其他线程能干活）。嵌入式通常固定少量线程并静态分配。

### Q32 ★★ 如何创建守护进程？为什么要 fork 两次？
**答案**：五步——① fork 后父进程退出（子进程被 init 收养）② setsid 创建新会话、脱离控制终端 ③ **再 fork 一次**，确保进程不是会话首进程 ④ chdir("/") ⑤ umask(0)、重定向标准 IO 到 /dev/null。
**fork 两次的原因**：第一次 fork + setsid 使子进程成为新会话的首进程；而会话首进程可以重新申请控制终端，所以再 fork 一次让孙进程成为非首进程，彻底无法获取终端。

### Q33 ★★ SIGTERM 和 SIGKILL 的区别？信号处理函数里不能做什么？
**答案**：
- **SIGTERM(15)**：可被捕获/忽略，进程可做清理后优雅退出（`kill` 的默认信号）
- **SIGKILL(9)**：内核直接终止，**不可捕获、不可忽略**，进程无法做任何清理
信号处理函数里**只能调用 async-signal-safe 函数**（write、_exit 可以；printf、malloc、free 不行，因为它们不可重入/可能加锁），否则可能死锁。

# 第三部分：易错速查

| 陷阱 | 记住 |
|---|---|
| 缺页中断 | 是**异常**不是中断 |
| 僵尸进程 | 已死未回收，占 PID |
| TIME_WAIT vs CLOSE_WAIT | 属 TCP 范畴，见 `23-网络协议.md` 2.3 |
| fork 返回值 | 父得子 PID，子得 0 |
| 共享内存 | 最快，但要自己同步 |
| 进程切换慢 | 因为换页表 + 刷 TLB |
| inode | 不含文件名 |
| 硬链接 | 不能跨分区、不能指目录 |
| LRU vs FIFO | FIFO 有 Belady 异常 |
| workqueue | 唯一能睡眠的下半部 |
| epoll | ET 模式必须读到 EAGAIN |
