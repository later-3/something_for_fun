# 第一部分：考点（20 条）

## 一、从 C 到 C++

### 1.1 C 和 C++ 的核心区别 ★
| | C | C++ |
|---|---|---|
| 编程范式 | 面向过程 | 面向过程 + 面向对象 + 泛型 |
| 类型检查 | 宽松（void* 自动转换） | 严格（须显式转换） |
| 函数 | 不支持重载 | 支持重载（name mangling） |
| 内存 | malloc/free | new/delete（调用构造/析构） |
| 引用 | 无 | 有 |
| 默认参数 | 无 | 有 |
| 结构体 | 只有数据 | 可有成员函数、访问控制、继承 |
| 命名空间 | 无 | namespace |

### 1.2 C++ 调用 C 代码：`extern "C"` ★★
```c
#ifdef __cplusplus
extern "C" {
#endif

void my_c_function(int);

#ifdef __cplusplus
}
#endif
```
**为什么需要**：C++ 支持重载，编译时对函数名做 **name mangling**（如 `void f(int)` 可能变成 `_Z1fi`），而 C 不做修饰。不用 `extern "C"`，链接阶段找不到 C 函数符号。
**嵌入式场景**：C 写的驱动/RTOS，用 C++ 写应用层时必须加。

## 二、内存管理

### 2.1 new/delete vs malloc/free ★★
| | new / delete | malloc / free |
|---|---|---|
| 本质 | **运算符**（可重载） | **库函数** |
| 构造/析构 | 分配后**调用构造函数** | 只分配原始内存 |
| 返回类型 | 类型指针（类型安全） | `void*`（C 中需强转，C++ 必须强转） |
| 失败 | 抛 `std::bad_alloc` | 返回 `NULL` |
| 大小 | 编译器自动计算 | 手动 `sizeof` |
| 配对 | `new`→`delete`，`new[]`→`delete[]` | `malloc`→`free` |
| 重载 | 可重载 `operator new` | 不可 |

**易错点**：
- `new[]` 必须配 `delete[]`，用 `delete` 只调第一个元素的析构 → 未定义行为
- `new` 出来的对象不能 `free`，`malloc` 出来的不能 `delete`（未定义行为）
- `new` 失败抛异常；不想要异常可用 `new (std::nothrow)`

```c
int *a = new int(10);            // 单对象，初始化为 10
int *b = new int[10]();          // 数组，值初始化（全 0）
delete a;
delete[] b;                      // 必须 delete[]
```

### 2.2 栈上 vs 堆上对象 ★
```cpp
void f() {
    MyClass a;                   // 栈对象：函数结束自动析构
    MyClass *b = new MyClass();  // 堆对象：必须手动 delete
}
```
**嵌入式建议**：优先栈/静态对象，避免堆（碎片 + 时间不确定）。

### 2.3 智能指针 ★
| 类型 | 语义 | 开销 |
|---|---|---|
| `unique_ptr` | **独占**所有权，不可拷贝、可移动 | 零额外开销（析构时 delete） |
| `shared_ptr` | **引用计数**，计数归零才释放 | 控制块（计数）+ 原子操作 |
| `weak_ptr` | 不增加计数，观察者；用 `lock()` 提升 | 无 |

**核心思想 RAII**（Resource Acquisition Is Initialization）：构造时获取资源，析构时自动释放 → **异常安全**，不会因为 return/throw 漏掉释放。

```cpp
std::unique_ptr<int> p(new int(5));
auto q = std::make_unique<int>(5);       // 推荐写法（C++14）
std::shared_ptr<int> s = std::make_shared<int>(5);
```
**shared_ptr 的坑**：两个对象互相 shared_ptr 持有 → 计数永不归零 → 泄漏。用 weak_ptr 打破环。

## 三、面向对象

### 3.1 类与对象基础
```cpp
class Point {
public:                          // 访问控制：public / protected / private
    Point(int x, int y) : x_(x), y_(y) {}   // 初始化列表（推荐，效率高）
    ~Point() {}                             // 析构函数
    int getX() const { return x_; }          // const 成员函数：承诺不改对象
private:
    int x_, y_;
};
```
**考点**：
- **初始化列表 vs 函数体内赋值**：初始化列表直接构造，函数体内是"先默认构造再赋值"，对类类型成员更慢；const 成员和引用成员**必须**用初始化列表
- 成员初始化顺序 = **声明顺序**，与初始化列表书写顺序无关

### 3.2 构造与析构的顺序 ★
**构造**：基类 → 成员对象（按声明顺序）→ 自身构造体
**析构**：自身析构体 → 成员对象（逆序）→ 基类
**为什么**：基类必须先构造好，派生类才能用；析构必须反过来，派生类先清理再销毁基类。

### 3.3 虚函数与多态 ★★（最高频）
```cpp
class Base {
public:
    virtual void show() { cout << "Base"; }   // 虚函数
    virtual void pure() = 0;                   // 纯虚函数 → 抽象类
    virtual ~Base() {}                         // 虚析构（重要！）
};
class Derived : public Base {
public:
    void show() override { cout << "Derived"; }  // 重写
};
Base *p = new Derived();
p->show();                    // 输出 Derived（动态绑定）
```

**实现机制**：
- 含虚函数的类，编译器生成**虚函数表 vtable**（一个类一张）
- 每个对象内有隐藏指针 **vptr** 指向本类的 vtable
- 调用虚函数：通过 vptr 查 vtable → 取函数地址 → 调用 = **运行时动态绑定**
- 普通函数是编译期静态绑定

**代价**：每对象多一个指针（8 字节）；调用多一次间接寻址；无法内联。

### 3.4 为什么基类析构必须是 virtual ★★
```cpp
Base *p = new Derived;
delete p;
```
若析构非虚：只调用 `Base::~Base`，**派生类的析构不执行** → 派生类的资源泄漏。
声明 `virtual ~Base()` 后，delete 会根据对象的动态类型正确调用 `Derived::~Derived` 再调基类。

**规则**：只要类可能被继承且通过基类指针 delete，析构必须 virtual。

### 3.5 重载 / 重写 / 隐藏 ★
| | 条件 | 决议时机 |
|---|---|---|
| **重载** overload | 同作用域、同名、**参数不同**（类型/个数/顺序） | 编译期 |
| **重写** override | 派生类重写基类 **virtual** 函数（签名相同） | 运行期 |
| **隐藏** hide/遮蔽 | 派生类有同名函数（不论是否虚、参数是否相同） | 编译期 |

**注意**：派生类重写后，基类的**其他同名重载版本都被隐藏**（需要 `using Base::f;` 引入）。

### 3.6 引用 vs 指针 ★★
| | 引用 | 指针 |
|---|---|---|
| 初始化 | **必须** | 可不初始化（危险） |
| 空值 | 不存在 | 可为 nullptr |
| 改绑 | 不能 | 能 |
| 算术运算 | 无 | 有 |
| sizeof | 对象大小 | 指针大小 |
| 多级 | 无（无引用的引用） | 有（二级指针） |

**底层**：引用通常用指针实现，但语言层语义更安全。
**参数传递**：优先 `const T&`（避免拷贝且不改原对象）。

### 3.7 const 相关（C++ 扩展）
```cpp
const int a = 10;                    // 常量，可作数组维度
int f(int) const;                    // const 成员函数：不能改成员变量
mutable int counter;                 // const 成员函数中仍可修改的成员
const int& r = a;                    // 常引用，延长临时对象生命周期
```

### 3.8 static 成员
```cpp
class Counter {
public:
    static int count;                // 静态成员变量：属于类，不属于对象
    static void reset() { count = 0; }   // 静态成员函数：无 this，只能访问静态成员
};
int Counter::count = 0;              // 必须在类外定义
```
**用途**：全局配置、对象计数、单例。

### 3.9 拷贝构造与赋值 ★
```cpp
class Buf {
public:
    Buf(const Buf &o);                  // 拷贝构造
    Buf &operator=(const Buf &o);       // 拷贝赋值
    Buf(Buf &&o) noexcept;              // 移动构造（C++11）
};
```
**默认行为**：编译器生成的拷贝是**浅拷贝**（逐成员复制）。含指针成员时必须写**深拷贝**，否则两个对象指向同一块内存 → 双重释放。

**三/五法则**：需要自定义析构、拷贝构造、拷贝赋值中的**一个**，通常三个都要（C++11 后加移动构造、移动赋值共五个）。

**删除拷贝**：`Buf(const Buf&) = delete;`（禁止拷贝，如 unique_ptr）。

### 3.10 移动语义（了解即可）
```cpp
std::string a = "hello";
std::string b = std::move(a);   // 转移资源，a 变成空
```
**原理**：右值引用 `T&&`，把临时对象的资源"偷"过来而不是深拷贝。`std::move` 只是类型转换（转成右值引用），本身不移动任何东西。

## 四、其他必考点

### 4.1 抽象类 vs 接口
- **抽象类**：含至少一个纯虚函数 `virtual void f() = 0;`，不能实例化
- **接口**：全部是纯虚函数 + 虚析构（C++ 无 interface 关键字，用抽象类模拟）

### 4.2 命名空间
```cpp
namespace drv {
    void init();
}
drv::init();                    // 限定调用
using namespace drv;            // 引入整个命名空间（头文件中禁用！）
using drv::init;                // 只引入一个（推荐）
```

### 4.3 默认参数
```cpp
void f(int a, int b = 10);
// 规则：默认参数必须从右往左连续；声明给默认值，定义不要再给
```

### 4.4 内联函数 vs 宏 ★
| | inline 函数 | 宏 |
|---|---|---|
| 类型检查 | 有 | 无 |
| 副作用 | 无（参数只求值一次） | 有（重复展开） |
| 调试 | 可调试 | 不可 |
| 展开时机 | 编译器决定 | 预处理必展开 |

**结论**：能用 inline 就不用宏（类型安全）；宏只用于条件编译和需要真正文本替换的场景。

### 4.5 四种类型转换（了解）
```cpp
static_cast<int>(3.14);                    // 编译期检查的常规转换
dynamic_cast<Derived*>(base_ptr);          // 运行期检查（多态类型），失败返回 nullptr
const_cast<char*>(const_ptr);              // 去掉 const（危险）
reinterpret_cast<uint32_t*>(&x);           // 位重解释（寄存器访问常用）
```
**嵌入式**：`reinterpret_cast` 用于寄存器地址映射；C 风格 `(type)expr` 会尝试多种顺序，不推荐。

### 4.6 引用与 const 在参数上的组合 ★
```cpp
void f(MyClass o);              // 值传递：拷贝构造一次（大对象慢）
void f(MyClass &o);             // 引用：可改原对象
void f(const MyClass &o);       // 常引用：不拷贝且不能改（**大对象首选**）
void f(MyClass &&o);            // 右值引用：接收临时对象，移动语义
```

### 4.7 结构体 vs 类
C++ 中 `struct` 和 `class` **唯一区别**：默认访问权限（struct 默认 public，class 默认 private）以及默认继承方式。

### 4.8 C++ 的坑（嵌入式常见）
- 全局对象在 main 之前构造、之后析构 → 顺序不确定（**静态初始化顺序问题**）
- 异常在嵌入式通常**禁用**（`-fno-exceptions`），new 失败要靠 nothrow
- RTTI 通常禁用（`-fno-rtti`），dynamic_cast 不可用
- 虚函数有 vtable 开销（Flash 占用），资源紧张时慎用
- 模板实例化会膨胀代码体积

### 4.9 STL 最小必要知识（不深考，但要知道）
| 容器 | 底层 | 查找 | 插入删除 | 场景 |
|---|---|---|---|---|
| `vector` | 动态数组 | O(1) 随机访问 | 尾部 O(1) 摊还 / 中间 O(n) | 默认首选 |
| `list` | 双向链表 | O(n) | O(1)（已定位） | 频繁中间插入 |
| `deque` | 分段数组 | O(1) 随机访问 | 两端 O(1) | 双端队列 |
| `map` | 红黑树 | O(logn) | O(logn) | 有序键值 |
| `unordered_map` | 哈希表 | O(1) 平均 | O(1) 平均 | 快速查找 |
| `set` | 红黑树 | O(logn) | O(logn) | 有序唯一集合 |

**嵌入式注意**：STL 会带来代码体积和动态内存分配，很多嵌入式项目禁用或用裁剪版（ETL）。

### 4.10 单例模式（考过）
```cpp
class Singleton {
public:
    static Singleton &instance() {
        static Singleton inst;      // C++11 起线程安全（局部静态变量保证只初始化一次）
        return inst;
    }
    Singleton(const Singleton &) = delete;
    Singleton &operator=(const Singleton &) = delete;
private:
    Singleton() = default;
};
```

# 第二部分：题目（20 题，答案已给）

### Q1 ★★ new/delete 和 malloc/free 的区别？（至少 5 条）
**答案**：① new 是运算符、malloc 是库函数；② new 分配后调构造函数、malloc 不调；③ new 失败抛 bad_alloc、malloc 返回 NULL；④ new 返回类型指针无需强转、malloc 返回 void*；⑤ new[] 必须配 delete[]、与 free 不可混用；⑥ new 可重载。

### Q2 ★★ 虚函数如何实现多态？代价是什么？
**答案**：含虚函数的类生成 vtable，对象内有 vptr 指向它；调用虚函数通过 vptr 查表 → 运行时动态绑定。
代价：每对象多一个指针空间、调用多一次间接寻址、无法内联优化。

### Q3 ★★ 为什么基类析构函数要声明为 virtual？
**答案**：`Base *p = new Derived; delete p;` 若析构非虚，只调用 Base 的析构，Derived 的析构不执行 → 派生类资源泄漏/未定义行为。声明 virtual 后按动态类型正确析构。

### Q4 ★ 重载、重写、隐藏的区别？
**答案**：
- 重载：同作用域同名不同参数，编译期决议
- 重写：派生类重写基类 virtual 函数（签名相同），运行期决议
- 隐藏：派生类同名函数遮蔽基类（不论是否虚），编译期决议；重写后基类其他同名重载也被隐藏

### Q5 ★ 引用和指针的区别？（至少 5 条）
**答案**：引用必须初始化、不能改绑、无空引用、无引用算术、sizeof 是对象大小；指针可不初始化（危险）、可改指向、可为 nullptr、有算术、sizeof 是指针大小。引用底层多由指针实现但语义更安全。

### Q6 ★ C++ 如何调用 C 代码？为什么需要？
**答案**：用 `extern "C" { ... }` 包裹声明。因为 C++ 有重载，编译期会对函数名做 name mangling；C 不做修饰。不加会导致链接阶段找不到符号。

### Q7 ★ 三种智能指针的区别和用途？
**答案**：unique_ptr 独占、不可拷贝可移动、零开销、默认首选；shared_ptr 引用计数共享、有控制块与原子操作开销、注意循环引用；weak_ptr 不增计数、用 lock() 提升、用于打破循环引用。核心是 RAII（构造获取、析构释放），保证异常安全。

### Q8 ★ 什么是 RAII？举例说明。
**答案**：Resource Acquisition Is Initialization——资源在构造时获取，析构时释放，依赖对象生命周期的确定性。
例：`std::lock_guard` 构造时加锁、析构时解锁，即使中间抛异常也会解锁；`std::unique_ptr` 析构时自动 delete。

### Q9 ★ 构造和析构的顺序？
**答案**：构造 = 基类 → 成员对象（按声明顺序）→ 自身构造体；析构完全相反 = 自身析构体 → 成员对象（逆序）→ 基类。
原因：基类必须先就绪派生类才能用；销毁必须派生类先清理再销毁基类。

### Q10 成员初始化列表和函数体内赋值有什么区别？
**答案**：初始化列表直接构造成员；函数体内赋值是先默认构造再赋值（多一次赋值开销）。
必须用初始化列表：const 成员、引用成员、无默认构造函数的类类型成员。
注意：初始化顺序按**声明顺序**，不是列表书写顺序。

### Q11 ★ 默认拷贝构造有什么问题？如何解决？
**答案**：默认是**浅拷贝**（逐成员复制），若类含指针成员，两个对象会指向同一块内存 → 一方释放后另一方成为悬空指针 → 双重释放崩溃。
解决：自定义拷贝构造与拷贝赋值实现**深拷贝**；或禁用拷贝（`= delete`）；或用智能指针管理资源。

### Q12 什么是抽象类？和接口什么关系？
**答案**：含纯虚函数（`virtual void f() = 0;`）的类叫抽象类，不能实例化，派生类必须实现所有纯虚函数才能实例化。
接口在 C++ 中用"全部纯虚函数 + 虚析构"的抽象类模拟（C++ 没有 interface 关键字）。

### Q13 ★ inline 函数和宏的区别？
**答案**：inline 有类型检查、参数只求值一次（无副作用）、可调试；宏是预处理文本替换、无类型检查、参数可能重复求值产生副作用、不可调试。能用 inline 就不用宏。

### Q14 ★ const 成员函数是什么？mutable 干什么用？
**答案**：`int get() const;` 承诺不修改对象的成员变量（const 对象只能调用 const 成员函数）。
mutable 修饰的成员变量即使在 const 成员函数中也能修改（用于缓存、计数器、互斥锁）。

### Q15 static 成员变量和静态成员函数的特点？
**答案**：静态成员变量属于类不属于对象，所有对象共享一份，必须在类外定义（C++17 可用 inline 变量）；静态成员函数没有 this 指针，只能访问静态成员，可用 `类名::函数()` 调用。

### Q16 移动语义是什么？std::move 做了什么？
**答案**：移动语义通过右值引用 `T&&` 把临时对象的资源"转移"而不是深拷贝，避免无谓的内存分配。
`std::move` 只是把左值**转换成右值引用**的类型转换（本身不移动任何东西），之后由移动构造/移动赋值完成实际转移。

### Q17 四种类型转换分别用于什么？
**答案**：static_cast（编译期检查的常规转换，如数值、继承层次上转）；dynamic_cast（运行期检查的多态类型转换，失败返回 nullptr，需 RTTI）；const_cast（去掉 const）；reinterpret_cast（位重解释，寄存器地址映射常用）。

### Q18 局部静态变量（函数内的 static）在 C++11 是线程安全的吗？
**答案**：是。C++11 规定局部静态变量的初始化是线程安全的（编译器生成一次性初始化保护），这是实现单例最简洁的写法：
```cpp
static Singleton &instance() { static Singleton s; return s; }
```

### Q19 什么是 name mangling？为什么会影响 C 和 C++ 混编？
**答案**：编译器把函数名、参数类型等信息编码进符号名的机制（如 `f(int)` → `_Z1fi`），用于支持重载。
C 不做 mangling，所以 C++ 调用 C 函数时符号名对不上 → 必须用 `extern "C"` 告诉编译器按 C 规则生成符号。

### Q20 C++ 在嵌入式中的常见限制？
**答案**：① 通常禁用异常（`-fno-exceptions`）和 RTTI（`-fno-rtti`）以省空间 ② 虚函数 vtable 占 Flash ③ 模板实例化膨胀代码 ④ 全局对象构造顺序不确定（静态初始化顺序问题） ⑤ STL 依赖动态内存，资源紧张时用 ETL 等裁剪库 ⑥ 优先栈/静态对象，少用堆。

# 第三部分：易错速查

| 陷阱 | 记住 |
|---|---|
| `delete` 数组 | 必须 `delete[]`，否则只析构第一个 |
| 基类析构非虚 | 通过基类指针 delete 派生对象 → 泄漏 |
| 默认拷贝构造 | 浅拷贝，含指针会双重释放 |
| 重写后基类重载被隐藏 | 需 `using Base::f;` |
| 初始化顺序 | 按声明顺序，不是列表顺序 |
| const 对象 | 只能调 const 成员函数 |
| `using namespace` | 头文件里禁用 |
| 静态初始化顺序 | 跨编译单元的全局对象构造顺序不确定 |
| shared_ptr 循环引用 | 用 weak_ptr 打破 |
| 引用不能为空 | 找不到对象就返回指针 |
