# 第一部分：考点（45 条）

## 一、关键字与修饰符

### 1.1 volatile ★★
**作用**：告诉编译器该变量可能被程序之外的因素改变，**禁止优化**——每次访问都必须从内存真实读取，不能缓存在寄存器里。

**三个必须用的场景**：
1. **中断服务程序修改、主循环读取的变量**（否则编译器可能认为循环变量不变而优化掉整个循环）
2. **硬件寄存器映射**（MMIO）：`*(volatile uint32_t *)0x40021000`
3. **RTOS 中多任务共享的标志变量**

**延伸（易错）**：
- `const volatile` **合法**：只读状态寄存器——软件不能写，但硬件会改
- volatile **不保证原子性**：32 位机上 64 位变量的 `++` 是两条指令，可被中断打断。要原子需关中断/原子指令/互斥
- volatile **不保证内存顺序**：多核/多线程的可见性还需要内存屏障

```c
volatile uint8_t rx_flag = 0;
void USART1_IRQHandler(void) { rx_flag = 1; }   // ISR 中修改
while (!rx_flag) { }                            // 主循环等待，不会被优化掉
```

### 1.2 static ★★
| 修饰对象 | 效果 |
|---|---|
| **局部变量** | **生命周期**变为整个程序（存 .data/.bss），只初始化一次，**作用域不变**（仍限函数内） |
| **全局变量** | **作用域**限本文件（内部链接，其他文件 extern 不到） |
| **函数** | 作用域限本文件（避免重名冲突） |

**嵌入式用法**：任务函数内 `static` 变量可在任务重启时保持状态；模块私有函数加 static 防止符号污染。

### 1.3 const ★
- `const` 修饰的变量**必须初始化**，之后不可改
- 与 `#define` 的区别见 1.4
- 修饰函数参数：`void print(const char *msg)` 承诺不修改入参
- 修饰成员函数（C++）：承诺不修改对象

### 1.4 const / #define / enum 定义常量的区别 ★
| | const | #define | enum |
|---|---|---|---|
| 本质 | 带类型的只读变量 | 预处理期**文本替换** | 整型常量集合 |
| 类型检查 | 有 | **无** | 有（整型） |
| 作用域 | 有 | 无（从定义点到文件尾） | 有 |
| 调试 | 能看符号 | 看不到 | 能看符号 |
| 占内存 | 占（.rodata，可能被优化） | 不占 | 不占 |
| 特殊能力 | — | 可拼接、条件编译、类型无关 | 可自动递增、可做类型约束 |
| 适合 | 有类型的常量 | 宏函数、条件编译、跨类型 | 状态机/错误码/枚举集合 |

### 1.5 extern / register / auto / inline
- **extern**：声明外部定义（变量或函数），告诉编译器"这个符号在别处定义"
- **register**：建议放寄存器（不能取地址），现代编译器基本忽略
- **auto**：默认存储类型，可省略
- **inline**：建议内联展开，省调用开销，代价是代码膨胀（适合短小函数；递归函数不能内联）

### 1.6 typedef vs #define ★
| | typedef | #define |
|---|---|---|
| 处理阶段 | 编译器 | 预处理器 |
| 类型检查 | 是 | 否 |
| 作用域 | 有 | 无 |
| 指针类型 | `typedef int *pint; pint a,b;` → 两个指针 | `#define pint int*` → `pint a,b;` → a 是指针，b 是 int |

**常见用法**：
```c
typedef unsigned char uint8_t;
typedef int (*handler_t)(int, void *);   // 函数指针类型，最常用
```

### 1.7 函数指针与 typedef ★
```c
int add(int a, int b);

int (*fp)(int, int) = add;        // 函数指针
fp(1, 2);  (*fp)(1, 2);           // 两种调用等价

typedef int (*handler_t)(int, int);   // 定义类型，可读性好
handler_t h = add;

int (*array[5])(int, int);        // 函数指针数组（状态机/跳转表）
```

**嵌入式用途**：回调、中断向量表、驱动 ops 结构（Linux 的 `file_operations`）、状态机跳转表、命令解析表。

### 1.8 位域（bit-field）★
```c
struct Flags {
    unsigned int ready : 1;    // 占 1 位
    unsigned int error : 1;
    unsigned int mode  : 2;    // 占 2 位，范围 0~3
};
```
**用途**：寄存器映射、协议位段解析、省内存。

**注意事项（考点）**：
- 位域**不能取地址**（`&f.ready` 非法，因为不是完整字节）
- 取值不能超过位数范围（2^n - 1）
- **与编译器实现相关**：位序（大端/小端）、跨字节的分配方式、是否允许跨存储单元——**跨平台/协议通信时不要直接用位域**，应手工位操作

### 1.9 联合体 union ★
**特性**：所有成员共享同一块内存，大小 = 最大成员大小（还要考虑对齐）。
**用途**：
1. **判断大小端**
2. 同一数据的不同解释（协议解析、浮点与字节互转）
3. 省内存

```c
union { int i; char c[4]; } u;
u.i = 0x12345678;
printf("%02X", u.c[0]);   // 78 → 小端；12 → 大端
```
**风险**：修改一个成员会破坏其他成员的值。

### 1.10 枚举 enum ★
```c
enum color { RED, BLUE, GREEN = -2, YELLOW, PINK };
// RED=0, BLUE=1, GREEN=-2, YELLOW=-1, PINK=0
printf("%d %d", BLUE, PINK);   // 输出 1 0
```
**规则**：默认从 0 开始递增；可手动赋值；**手动赋值后后续成员从该值继续递增**（故 PINK = -2+1+1 = 0）。
**用途**：状态机、错误码、设备模式。比 #define 好：有类型检查、可调试、自动递增。

### 1.11 柔性数组（Flexible Array Member）
```c
struct Packet {
    uint16_t len;
    uint8_t  data[];      // 柔性数组，必须是最后一个成员，不占 sizeof
};
// sizeof(struct Packet) == 2（只算 len）
struct Packet *p = malloc(sizeof(struct Packet) + payload_len);
```
**用途**：变长数据结构（协议包、消息），一次分配内存且内存连续。

### 1.12 可变参数 ★
```c
#include <stdarg.h>
int sum(int count, ...) {
    va_list args;
    va_start(args, count);          // 从最后一个固定参数开始
    int total = 0;
    for (int i = 0; i < count; i++) total += va_arg(args, int);
    va_end(args);
    return total;
}
```
**要点**：必须有至少一个固定参数；调用者与实现者必须约定参数类型和数量（C 语言不做检查，`printf` 靠格式串）。

### 1.13 常见关键字补充
| 关键字 | 作用 |
|---|---|
| `sizeof` | 编译期运算符，求字节数（不是函数） |
| `__attribute__((packed))` | GCC 取消结构体对齐（协议解析用） |
| `__attribute__((aligned(n)))` | 强制对齐（DMA 缓冲要求） |
| `restrict` | 承诺指针是唯一访问路径，帮助编译器优化 |
| `_Static_assert` / `static_assert` | 编译期断言（C11），检查 sizeof/常量 |

## 二、指针与数组

### 2.1 指针 vs 数组名 ★
| | 数组名 | 指针 |
|---|---|---|
| 本质 | 数组首元素地址，**常量** | 变量，可改变指向 |
| 赋值 | 不能赋值 | 可赋值 |
| `sizeof` | 整个数组大小 | 指针大小（8 字节 / 32 位系统 4 字节） |
| `&` | `&arr` 是数组指针 `int(*)[N]` | `&p` 是二级指针 |

**数组名退化为指针的情况**：作为函数参数、参与算术运算、赋值给指针。
**不退化的例外**：`sizeof(arr)`、`&arr`、`sizeof` 内部——这三处数组名仍是数组类型。

```c
int arr[5] = {1,2,3,4,5};
int *p = arr;
// arr = p;      // 错误：数组名是常量
p++;             // 正确：指针可移动
sizeof(arr);     // 20（假设 int 4 字节）
sizeof(p);       // 8
sizeof(&arr);    // 8（数组指针大小）
```

### 2.2 指针谱系（必须一眼分清）★★
```c
int *a[10];        // 指针数组：10 个 int*，sizeof = 10*8 = 80
int (*a)[10];      // 数组指针：指向 int[10] 的指针，sizeof = 8，a+1 跳 40 字节
int (*f)(int);     // 函数指针：指向 int(int) 的函数
int *f(int);       // 指针函数：返回 int* 的函数
int **pp;          // 二级指针：指向指针的指针
const int *p;      // 指向 const int 的指针（*p 不可改，p 可改）
int * const p;     // const 指针（p 不可改，*p 可改）
const int * const p;  // 都不可改
```
**记忆口诀**：`*` 读作 "pointer to"；**从右往左读**。

### 2.3 二级指针的使用场景 ★
1. **在函数内修改指针本身**（传出参数）：
```c
void alloc(char **p) { *p = malloc(100); }   // 必须传二级指针
char *buf = NULL; alloc(&buf);
```
2. 二维数组 / 字符串数组传参：`char **argv`
3. 链表操作中修改头指针

### 2.4 空指针 / 野指针 / 悬空指针 ★
| 概念 | 定义 | 防范 |
|---|---|---|
| **空指针** | `NULL`，不指向任何对象 | 使用前判空 |
| **野指针** | 未初始化的指针，指向随机地址 | 定义时初始化为 NULL |
| **悬空指针** | 指向已释放/已失效内存 | free 后立即置 NULL |

```c
int *p;              // 野指针
*p = 10;             // 未定义行为

int *q = malloc(4);
free(q);
*q = 10;             // 悬空指针，未定义行为
q = NULL;            // 正确做法
```

### 2.5 void* 指针 ★
- 可指向任意类型（通用指针）
- **不能直接解引用**（必须先强转）
- **不能进行指针算术运算**（GCC 扩展允许，但非标准）
- `malloc` 返回 `void*`，因此 C 中不需强转（C++ 需要）

```c
void *p = malloc(100);
int *ip = (int *)p;     // 必须转换
// *p = 10;             // 错误
```

### 2.6 指针运算与偏移（嵌入式高频）★
```c
struct S { char a; int b; char c; };          // sizeof = 12
#define offsetof(type, member) ((size_t)&((type *)0)->member)
offsetof(struct S, b)   // 4

#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))
```
**这是 Linux 内核最核心的宏**（链表、工作队列全靠它）——你的内核背景在这里是优势。

### 2.7 指针与字符串
```c
char s[] = "abc";       // 栈上数组，可修改，sizeof = 4
char *p = "abc";        // p 在栈，字面量在 .rodata，**不可修改**
// p[0] = 'x';          // 未定义行为（可能段错误）
```

## 三、内存

### 3.1 内存分区 ★★
```
高地址
 ┌──────────────┐
 │  栈 stack     │ 局部变量、函数参数、返回地址；向下增长；自动管理
 ├──────────────┤
 │      ↓       │
 │   空闲区域    │
 │      ↑       │
 ├──────────────┤
 │  堆 heap      │ malloc/free；向上增长；手动管理；会碎片化
 ├──────────────┤
 │  .bss         │ 未初始化全局/静态变量；启动时清零；不占 Flash
 ├──────────────┤
 │  .data        │ 已初始化全局/静态变量；从 Flash 拷到 RAM
 ├──────────────┤
 │  .rodata      │ const 全局、字符串字面量；只读
 ├──────────────┤
 │  .text        │ 函数代码；只读，可直接 XIP 执行
 └──────────────┘
低地址
```
**嵌入式关键点**：
- Flash 存 .text + .rodata + .data 初值；RAM 存 .data + .bss + 堆 + 栈
- 启动代码负责：拷贝 .data 到 RAM、.bss 清零
- `const` 修饰的全局会进 .rodata（省 RAM，留在 Flash）

### 3.2 堆 vs 栈 ★
| | 栈 | 堆 |
|---|---|---|
| 管理 | 编译器自动 | 手动（malloc/free） |
| 速度 | 快（栈指针移动） | 慢（需查找空闲块） |
| 碎片 | 无 | **有** |
| 大小 | 小（Linux 默认 8MB，MCU 几 KB） | 大（受限于可用 RAM） |
| 失败 | 栈溢出（崩溃） | 返回 NULL |
| 生命周期 | 函数退出即释放 | 显式 free 才释放 |

### 3.3 内存对齐 ★★
**规则**：
1. 每个成员的偏移 = 自身大小（或 `#pragma pack` 值）的整数倍
2. 结构体总大小 = 最大成员大小的整数倍

```c
struct A { char a; int b; char c; };   // 1 + 3填 + 4 + 1 + 3填 = 12
struct B { int b; char a; char c; };   // 4 + 1 + 1 + 2填 = 8
```
**结论**：成员**按大小降序排列**最省内存。

**为什么要对齐**：CPU 按字长访问内存，未对齐需要两次访问（性能）或直接触发异常（老 ARM、部分架构）。

### 3.4 #pragma pack / __attribute__((packed)) ★
```c
#pragma pack(1)          // 取消对齐
struct A { char a; int b; char c; };   // sizeof = 6
#pragma pack()
```
**好处**：协议帧、Flash 存储结构体时省空间、与协议字节对齐一致。
**风险**：成员可能在奇数地址，某些架构访问未对齐地址会出错或变慢；取未对齐成员的地址可能有问题。
**替代**：`__attribute__((packed))` 只作用于单个结构体。

### 3.5 大小端 ★
| 类型 | 低地址存 | 例（0x12345678） |
|---|---|---|
| **小端**（little-endian） | 低字节 | 78 56 34 12（x86、ARM 默认） |
| **大端**（big-endian） | 高字节 | 12 34 56 78（网络字节序、PowerPC） |

**判断代码**：
```c
int x = 1;
if (*(char *)&x == 1) puts("小端"); else puts("大端");

// 或 union
union { int i; char c; } u = {.i = 1};
if (u.c == 1) puts("小端");
```
**协议解析的坑**：网络字节序是大端，主机可能是小端，必须 `htons/htonl/ntohs/ntohl` 转换。

### 3.6 内存对齐对 DMA 的影响（嵌入式场景题）★
DMA 通常要求缓冲区**地址和长度按 4 字节（或 cache line）对齐**。
- 未对齐可能导致传输错误或性能下降
- 有 cache 的 MCU（Cortex-M7/MPU）：DMA 写内存前要 **clean cache**，读内存前要 **invalidate cache**，否则读到旧数据

### 3.7 浮点数的内存布局 ★
| 类型 | 总位数 | 符号 | 指数 | 尾数 |
|---|---|---|---|---|
| float | 32 | 1 | 8 | 23 |
| double | 64 | 1 | 11 | 52 |

**考点**：浮点数不能直接用 `==` 比较（精度误差），应用 `fabs(a-b) < EPS`。
**嵌入式**：无 FPU 的 MCU 用软件浮点（慢），优先用定点数（如放大 1000 倍的整数）。

### 3.8 内存泄漏与排查 ★
**定义**：malloc 后未 free，长期运行内存耗尽。
**嵌入式排查手段**：
- 静态分析（clang-tidy、Cppcheck）
- 运行时统计 malloc/free 配对（重载 malloc 加计数）
- valgrind（有 OS 环境）、AddressSanitizer
- 显式禁止：用静态分配/内存池代替 malloc

### 3.9 为什么嵌入式尽量不用 malloc ★★
1. **碎片化**：长时间运行后堆被切碎，即使总空闲够也可能分配失败
2. **执行时间不确定**：查找空闲块的时间不可预测 → 破坏实时性
3. **失败处理麻烦**：资源受限环境下 malloc 失败要有兜底
4. FreeRTOS 的 heap_1/heap_2 甚至不支持 free

**替代方案**：
- **静态分配**：编译期确定数组 + 索引
- **内存池**：预分配固定大小块的数组，用空闲链表管理（O(1) 分配，无碎片）
- FreeRTOS 的 `xTaskCreateStatic()` / `pvPortMalloc`

## 四、字符串与常用库函数（手写高频）

### 4.1 sizeof vs strlen ★★
| | sizeof | strlen |
|---|---|---|
| 性质 | 编译期运算符 | 运行时函数 |
| 作用 | 占的字节数 | 到 `\0` 的字符数（不含 `\0`） |
| 数组 vs 指针 | 数组=总大小，指针=8 | 一样，都数到 `\0` |

```c
char s[] = "abc";
char *p = "abc";
sizeof(s);   // 4
strlen(s);   // 3
sizeof(p);   // 8
strlen(p);   // 3
```

### 4.2 手写 strcpy（考虑重叠与边界）★
```c
char *my_strcpy(char *dst, const char *src) {
    if (!dst || !src) return NULL;
    char *d = dst;
    while ((*d++ = *src++) != '\0');
    return dst;
}
```

### 4.3 手写 memcpy（考虑内存重叠）★
```c
void *my_memcpy(void *dst, const void *src, size_t n) {
    if (!dst || !src || n == 0) return dst;
    unsigned char *d = (unsigned char *)dst;
    const unsigned char *s = (const unsigned char *)src;
    if (d <= s) {                   // 正向拷贝（含 d == s 的情形）
        while (n--) *d++ = *s++;
    } else {                        // d > s：反向拷贝，避免重叠覆盖
        d += n; s += n;
        while (n--) *--d = *--s;
    }
    return dst;
}
```
**注**：标准库 `memcpy` 不保证处理重叠（重叠应用 `memmove`）。笔试常要求"考虑重叠"，直接按 memmove 写。

### 4.4 手写 strlen / strcmp / strcat
```c
size_t my_strlen(const char *s) {
    const char *p = s;
    while (*p) p++;
    return p - s;
}

int my_strcmp(const char *a, const char *b) {
    while (*a && *a == *b) { a++; b++; }
    return (unsigned char)*a - (unsigned char)*b;
}

char *my_strcat(char *dst, const char *src) {
    char *d = dst;
    while (*d) d++;                       // 找到结尾
    while ((*d++ = *src++) != '\0');
    return dst;
}
```

### 4.5 手写 atoi（考虑正负号与非法字符）★
```c
int my_atoi(const char *s) {
    if (!s) return 0;
    while (*s == ' ' || *s == '\t') s++;   // 跳过空白
    int sign = 1;
    if (*s == '-' || *s == '+') { if (*s == '-') sign = -1; s++; }
    int num = 0;
    while (*s >= '0' && *s <= '9') num = num * 10 + (*s++ - '0');
    return sign * num;
}
```

### 4.6 手写字符串查找子串 ★（西门子真题）
```c
char *my_strstr(const char *hay, const char *needle) {
    if (!hay || !needle) return NULL;
    if (!*needle) return (char *)hay;
    for (; *hay; hay++) {
        const char *h = hay, *n = needle;
        while (*h && *n && *h == *n) { h++; n++; }
        if (!*n) return (char *)hay;      // needle 匹配完
    }
    return NULL;
}
```
**复杂度**：O(n*m) 朴素算法；KMP 优化到 O(n+m)（知道存在即可）。

### 4.7 printf 返回值 ★（易错题）
```c
int i = 43;
printf("%d\n", printf("%d", printf("%d", i)));
```
**输出：4321**
- 最内层 `printf("%d", 43)` 输出 "43"，返回 **2**（输出字符数，不含 `\0`）
- 中间层 `printf("%d", 2)` 输出 "2"，返回 1
- 最外层 `printf("%d\n", 1)` 输出 "1" 加换行
→ 屏幕上依次是 `43` `2` `1`，即 4321

### 4.8 数组越界与缓冲区溢出 ★
```c
char buf[8];
strcpy(buf, "123456789");   // 溢出 2 字节，破坏栈上相邻数据
```
**后果**：栈溢出 → 返回地址被覆盖 → 崩溃或可被利用（缓冲区溢出攻击）。
**防范**：用 `strncpy`/`snprintf`、检查长度、`__attribute__((stack_protect))`、MPU。

## 五、宏与预处理

### 5.1 宏的陷阱 ★★
```c
#define SQUARE(x) x*x             // 错
SQUARE(2+3) → 2+3*2+3 = 11        // 不是 25

#define SQUARE(x) ((x)*(x))       // 对
SQUARE(i++) → ((i++)*(i++))       // 仍然错：i 被自增两次
```
**规则**：① 参数和整体都要加括号 ② 避免副作用（不要传 ++ 表达式）③ 复杂宏用 `do { } while(0)` 包裹。

### 5.2 `#` 与 `##` ★
```c
#define STR(x) #x                // 字符串化：STR(abc) → "abc"
#define CAT(a,b) a##b            // 拼接：CAT(foo,bar) → foobar
```
**用途**：自动生成变量名/函数名、调试打印（`#x` 输出表达式原文）。

### 5.3 do{}while(0) 的作用 ★
```c
#define SAFE_FREE(p) do { free(p); p = NULL; } while(0)

if (cond) SAFE_FREE(p);    // 正确：整个宏是一条语句
else ...
```
**不用 do-while 的后果**：`#define SAFE_FREE(p) free(p); p=NULL;` 在 if/else 中会被拆成两条语句，else 会配对错误。
**为什么不用 `{ }`**：`if (cond) { free(p); p=NULL; };` 后面多出的分号会引发空语句问题。

### 5.4 编译四阶段 ★★
```
.c --预处理--> .i --编译--> .s --汇编--> .o --链接--> 可执行
```
| 阶段 | 做什么 | 产物 |
|---|---|---|
| 预处理 | 展开 `#include`、替换 `#define`、处理 `#ifdef`、删注释 | .i |
| 编译 | C → 汇编（语法分析、优化） | .s |
| 汇编 | 汇编 → 机器码 + 符号表 | .o |
| 链接 | 符号解析 + 重定位，合并库 | 可执行 |

**GCC 命令**：
```bash
gcc -E main.c -o main.i
gcc -S main.c -o main.s
gcc -c main.c -o main.o
gcc main.o -o main
```

### 5.5 头文件防重复包含
```c
#ifndef __MY_HEADER_H__
#define __MY_HEADER_H__
// 内容
#endif

// 或（非标准但所有主流编译器支持）
#pragma once
```

### 5.6 静态库 vs 动态库
| | 静态库（.a / .lib） | 动态库（.so / .dll） |
|---|---|---|
| 链接方式 | 编译时拷入可执行文件 | 运行时加载 |
| 体积 | 可执行文件大 | 可执行文件小 |
| 更新 | 需重新编译 | 替换库文件即可 |
| 内存 | 每个进程各有一份 | 多进程共享 |
| 嵌入式 | **常用**（无 OS 动态加载） | 需要 OS 支持 |

## 六、嵌入式 C 惯例（考点型）

### 6.1 寄存器访问的标准写法 ★
```c
// 方式1：宏定义地址 + volatile 指针
#define GPIOA_BASE  0x40020000UL
#define GPIOA_ODR   (*(volatile uint32_t *)(GPIOA_BASE + 0x14))
GPIOA_ODR |= (1 << 5);          // 置位 PA5

// 方式2：位带操作（Cortex-M3/M4 支持，原子操作）
// 方式3：结构体映射（HAL 库风格）
typedef struct {
    volatile uint32_t MODER;
    volatile uint32_t OTYPER;
    // ...
} GPIO_TypeDef;
#define GPIOA ((GPIO_TypeDef *)GPIOA_BASE)
```
**必须 volatile**：否则编译器可能把多次读合并/删除。

### 6.2 ISR 编写规范 ★★
**可以做**：清中断标志、读/写寄存器、把数据放入缓冲区、发信号量/队列、置标志位
**不能做**：
- `printf`（慢、不可重入、可能阻塞）
- `malloc/free`（不可重入、耗时不确定）
- 浮点运算（若中断不保存 FPU 上下文）
- 调用可能阻塞的 RTOS API（必须用 `FromISR` 版本）
- 长时间循环/延时
- 调用不可重入函数

**原则**：**上半部短（硬件相关），下半部慢（业务逻辑）**——详见 `12-操作系统.md` 6.1 / `24-嵌入式系统基础.md`。

### 6.3 可重入函数 ★
**定义**：可被多个执行流同时调用而不出错的函数。
**不可重入的原因**：
1. 使用全局/静态变量
2. 返回指向静态数据的指针
3. 调用 malloc/free
4. 使用标准 IO（printf、stdio 缓冲区）

**判断**：只操作参数和局部变量的函数通常可重入。

### 6.4 位操作技巧（背下来）★
```c
// 基本操作
#define SET_BIT(x, n)     ((x) |=  (1u << (n)))
#define CLR_BIT(x, n)     ((x) &= ~(1u << (n)))
#define TOG_BIT(x, n)     ((x) ^=  (1u << (n)))
#define GET_BIT(x, n)     (((x) >> (n)) & 1u)

// 多位置位（把 bit10~13 设为 0101）
x = (x & ~(0xF << 10)) | (0x5 << 10);

// 位段提取/插入
#define EXTRACT(x, hi, lo)  (((x) >> (lo)) & ((1u << ((hi)-(lo)+1)) - 1))
#define INSERT(x, v, hi, lo) (((x) & ~(((1u<<((hi)-(lo)+1))-1) << (lo))) | (((v) & ((1u<<((hi)-(lo)+1))-1)) << (lo)))

// 其他技巧
x & (x-1)          // 清除最低位的 1（判断是否是 2 的幂：x & (x-1) == 0）
x & (-x)           // 取最低位的 1（lowbit）
x | (x+1)          // 把最低位的 0 置 1
__builtin_popcount(x)   // 数 1 的个数（GCC 内建）
```

### 6.5 整数提升与隐式转换（坑）★
```c
unsigned int a = 5;
int b = -10;
if (a > b) printf("a > b");     // 输出 a > b —— 因为 b 被转成无符号的极大值！
```
**规则**：混合运算时低等级类型向高等级转；有符号与无符号混合时**有符号转无符号**（陷阱）。
**建议**：避免有符号/无符号混合比较，开 `-Wsign-compare`。

### 6.6 char 的有符号性
`char` 在 x86/ARM 上默认**有符号**（-128~127），但**标准未规定**。
→ 处理字节数据（如 0xFF）时应显式用 `unsigned char`/`uint8_t`，否则会变成 -1。

### 6.7 C 常见未定义行为（UB）清单
- 解引用空/野指针
- 数组越界
- 有符号整数溢出
- 除以 0
- 修改字符串字面量
- 未初始化变量读取
- 同一表达式中对同一变量多次修改（`i = i++`）
- free 后使用（use-after-free）、重复 free
- 返回局部变量地址
- 位域跨平台依赖

## 九、嵌入式数据结构与存储

### 9.1 环形缓冲区（Ring Buffer）★
**用途**：串口收发、ADC 采样、日志——**无锁的 ISR ↔ 主循环数据通路**。

```c
typedef struct {
    uint8_t buf[256];
    volatile uint16_t head;   // 写指针（ISR 修改）
    volatile uint16_t tail;   // 读指针（主循环修改）
} ring_t;

// ISR 中写入
int ring_put(ring_t *r, uint8_t d) {
    uint16_t next = (r->head + 1) % sizeof(r->buf);
    if (next == r->tail) return -1;     // 满
    r->buf[r->head] = d;
    r->head = next;
    return 0;
}

// 主循环读取
int ring_get(ring_t *r, uint8_t *d) {
    if (r->head == r->tail) return -1;  // 空
    *d = r->buf[r->tail];
    r->tail = (r->tail + 1) % sizeof(r->buf);
    return 0;
}
```
**要点**：head/tail 用 `volatile`；单生产者单消费者时无需锁；用"留一个空位"区分满/空。

### 9.2 内存池 ★
```c
#define POOL_SIZE 10
#define BLOCK_SIZE 64

static uint8_t pool[POOL_SIZE][BLOCK_SIZE];
static uint8_t in_use[POOL_SIZE] = {0};

void *pool_alloc(void) {
    for (int i = 0; i < POOL_SIZE; i++)
        if (!in_use[i]) { in_use[i] = 1; return pool[i]; }
    return NULL;                  // 池满
}
void pool_free(void *p) {
    for (int i = 0; i < POOL_SIZE; i++)
        if (p == pool[i]) { in_use[i] = 0; return; }
}
```
**优点**：O(1) 分配、无碎片、时间确定 → 适合实时系统。

### 9.3 状态机（表驱动）★
```c
typedef enum { IDLE, RUN, STOP } state_t;
typedef struct { state_t cur; int event; state_t next; void (*action)(void); } trans_t;

static trans_t table[] = {
    {IDLE, EV_START, RUN,  do_start},
    {RUN,  EV_STOP,  STOP, do_stop},
    {STOP, EV_RESET, IDLE, do_reset},
};
void fsm_handle(state_t *s, int ev) {
    for (size_t i = 0; i < sizeof(table)/sizeof(table[0]); i++)
        if (table[i].cur == *s && table[i].event == ev) {
            table[i].action(); *s = table[i].next; return;
        }
}
```
**优点**：用数据表代替 switch-case 大泥球，易扩展、易验证。

# 第二部分：题目（45 题，答案已给）

## 一、关键字（12 题）

### Q1 ★ volatile 的作用？三个必须用的场景？
**答案**：禁止编译器优化，每次从内存真实读取。场景：① 中断修改、主循环读取的变量 ② 硬件寄存器映射 ③ 多任务共享标志。
补充：`const volatile` 合法（只读状态寄存器）；volatile **不保证原子性**，也不保证内存顺序。

### Q2 ★ static 修饰局部变量、全局变量、函数分别什么效果？
**答案**：
- 局部变量：生命周期变为整个程序（.data/.bss），只初始化一次，作用域不变
- 全局变量：作用域限本文件（内部链接）
- 函数：作用域限本文件

### Q3 ★ const、#define、enum 定义常量有什么区别？
**答案**：见 1.4 表格。要点：const 有类型有作用域可调试；#define 是文本替换无类型检查；enum 是整型常量集合，可自动递增，适合状态码。

### Q4 ★ typedef 和 #define 的区别？举一个 typedef 更好的例子。
**答案**：typedef 由编译器处理、有类型检查、有作用域；#define 是预处理器文本替换。
关键差异在指针类型定义：
```c
typedef int *pint; pint a, b;   // a 和 b 都是 int*
#define pint int*
pint a, b;                      // 展开为 int *a, b → a 是指针，b 是 int
```

### Q5 *#define SQUARE(x) x*x 有什么问题？
**答案**：`SQUARE(2+3)` 展开为 `2+3*2+3 = 11`（不是 25）。应写 `((x)*(x))`。
即使加括号仍有副作用问题：`SQUARE(i++)` → `((i++)*(i++))`，i 被自增两次。

### Q6 宏里 `#` 和 `##` 的作用？
**答案**：`#` 把参数转换成字符串字面量；`##` 拼接两个 token 成一个（如 `CAT(foo,bar)` → `foobar`）。

### Q7 do{}while(0) 在宏里为什么常用？
**答案**：让多条语句的宏在 `if/else` 中表现为**一条语句**，避免语句拆分导致 else 配对错误；同时末尾分号的语义也更自然。
```c
#define F(p) do { free(p); p = NULL; } while(0)
if (c) F(p); else ...     // 正确
```

### Q8 位域是什么？有什么注意事项？
**答案**：结构体中指定字段占用的位数。
注意事项：① 不能取地址 ② 值不能超出位数范围 ③ **与编译器实现相关**（位序、跨字节分配），协议/跨平台场景不要用，应手工位操作。

### Q9 union 有什么特性？三个用途？
**答案**：所有成员共享同一块内存，大小 = 最大成员大小。
用途：① 判断大小端 ② 同一数据的多种解释（协议解析、float↔字节） ③ 省内存。

### Q10 enum 默认值规则？
```c
enum color { RED, BLUE, GREEN = -2, YELLOW, PINK };
printf("%d %d", BLUE, PINK);
```
**答案**：输出 `1 0`。默认从 0 递增：RED=0, BLUE=1, GREEN=-2（手动），YELLOW=-1, PINK=0（-2 递增两次）。

### Q11 柔性数组是什么？怎么用？
**答案**：结构体最后一个成员声明为 `type data[]`（不指定长度），不占 sizeof；分配时用 `malloc(sizeof(struct) + n)`，数据与头在同一块连续内存里。适合变长协议包。

### Q12 可变参数函数怎么实现？有什么约束？
**答案**：用 `<stdarg.h>` 的 `va_list / va_start / va_arg / va_end`。
约束：至少一个固定参数（va_start 需要它定位）；类型和数量 C 语言不检查，必须由调用约定保证（如 printf 的格式串）。

## 二、指针与数组（10 题）

### Q13 ★★ 指针和数组名的区别？
**答案**：数组名是首元素地址且是**常量**（不能赋值），指针是变量（可改变指向）。
`sizeof` 不同：`sizeof(arr)` = 整个数组，`sizeof(p)` = 指针大小（8）。
**数组名退化**：作为函数参数、参与算术、赋值给指针时退化为指针；
**不退化的例外**：`sizeof(arr)`、`&arr`（数组指针 `int(*)[N]`）。

### Q14 ★★ 辨析：`int *a[10]` 和 `int (*a)[10]`
**答案**：
- `int *a[10]`：**指针数组**（10 个 int*），sizeof = 80
- `int (*a)[10]`：**数组指针**（指向 int[10]），sizeof = 8，`a+1` 跳过 40 字节

### Q15 指针函数 vs 函数指针？
**答案**：
- `int *f(int)`：指针函数，**返回 int* 的函数**
- `int (*f)(int)`：函数指针，**指向函数的指针**，用于回调/跳转表/驱动 ops

### Q16 ★ 什么时候必须用二级指针？
**答案**：需要在函数内**修改指针本身的指向**时（传出参数）。
```c
void alloc(char **p) { *p = malloc(100); }
char *buf = NULL; alloc(&buf);
```
其他场景：二维数组/字符串数组传参（`char **argv`）、修改链表头指针。

### Q17 ★ 空指针、野指针、悬空指针的区别？
**答案**：
- 空指针：`NULL`，不指向任何对象
- 野指针：未初始化，指向随机地址
- 悬空指针：指向已释放/失效的内存
防护：定义即初始化为 NULL、free 后置 NULL、使用前判空。

### Q18 void* 有什么特点？
**答案**：可指向任意类型；不能直接解引用（须强转）；不能做指针算术（标准未定义，GCC 扩展允许）；`malloc` 返回 void*。

### Q19 ★ 手写 offsetof 宏，并说明 container_of 怎么用它。
**答案**：
```c
#define offsetof(type, member) ((size_t)&((type *)0)->member)
#define container_of(ptr, type, member) \
    ((type *)((char *)(ptr) - offsetof(type, member)))
```
原理：把 0 地址当作结构体起始，取成员地址即为偏移。`container_of` 由成员指针反推结构体首地址——Linux 内核链表的核心技巧。

### Q20 ★ `const int *p`、`int * const p`、`const int * const p` 的区别？
**答案**：从右往左读（`*` 读作 pointer to）：
- `const int *p`：pointer to const int → `*p` 不可改，p 可改
- `int * const p`：const pointer to int → p 不可改，`*p` 可改
- `const int * const p`：都不可改

### Q21 指针能进行哪些运算？
**答案**：`+`/`-` 整数（按元素大小移动）、指针相减（得到元素个数）、比较（同一数组内有意义）、`++`/`--`、下标 `p[i]`。
`void*` 和函数指针不能做算术（标准）。

### Q22 数组 `a` 与 `&a` 的区别？
**答案**：`a` 退化为首元素指针（`int*`），`&a` 是指向整个数组的指针（`int(*)[N]`）。数值相同、类型不同：`a+1` 跳 1 个元素，`&a+1` 跳整个数组。

## 三、内存（10 题）

### Q23 ★★ 程序的内存分区？各放什么？
**答案**：.text（代码）、.rodata（const 全局、字符串字面量）、.data（已初始化全局/静态）、.bss（未初始化全局/静态，启动清零）、堆（malloc，向上长）、栈（局部变量/参数/返回地址，向下长）。

### Q24 ★★ 下列变量在哪个区？
```c
int g1; int g2 = 10; const int g3 = 20;
void f(void) { int l; static int s; char *p = malloc(10); char *q = "hello"; }
```
**答案**：g1→.bss；g2→.data；g3→.rodata；l→栈；s→.bss；p 在栈、malloc 的内存在堆；q 在栈、"hello" 在 .rodata。

### Q25 ★★ 结构体对齐计算：
```c
struct A { char a; int b; char c; };      // ?
struct B { int b; char a; char c; };      // ?
struct C { char a; short b; char c; };    // ?（注意：最大成员是 short，2 字节对齐）
```
（32 位系统，默认对齐）
**答案**：A = 1+3填+4+1+3填 = **12**；B = 4+1+1+2填 = **8**；C = 1+1填+2+1+1填 = **6**。
规律：成员偏移是自己大小的整数倍；总大小是最大成员的整数倍；**降序排列更省**。

### Q26 ★ `#pragma pack(1)` 后 struct A 是多少？有什么风险和用途？
**答案**：`sizeof(A) = 6`（无填充）。
用途：协议帧结构、Flash 存储结构体、与外部二进制格式对齐。
风险：成员可能位于奇数地址，某些架构访问未对齐地址会异常或变慢；取未对齐成员的地址可能有问题。

### Q27 ★★ 大小端是什么？写代码判断。
**答案**：大端=高字节存低地址（网络字节序），小端=低字节存低地址（x86/ARM 默认）。
```c
int x = 1;
if (*(char *)&x == 1) puts("小端"); else puts("大端");
```
协议解析坑：网络字节序是大端，需 `htons/htonl/ntohs/ntohl` 转换。

### Q28 ★ 堆和栈的区别？（至少 5 条）
**答案**：管理方式（自动/手动）、速度（快/慢）、碎片（无/有）、大小（小/大）、生命周期（函数退出即释放/free 才释放）、失败表现（栈溢出崩溃/返回 NULL）。

### Q29 ★★ 为什么嵌入式系统尽量不用 malloc？替代方案？
**答案**：
原因：① 碎片化导致长期运行后分配失败 ② 执行时间不确定，破坏实时性 ③ 失败处理复杂 ④ FreeRTOS 的 heap_1/2 不支持 free。
替代：静态分配（数组+索引）、内存池、`xTaskCreateStatic`。

### Q30 内存泄漏怎么排查？
**答案**：静态分析（clang-tidy/Cppcheck）、重载 malloc/free 计数配对、valgrind/AddressSanitizer（有 OS）、代码审查配对。嵌入式优先靠"不用动态分配"从源头避免。

### Q31 ★ DMA 对内存有什么要求？有 cache 的 MCU 要注意什么？
**答案**：DMA 缓冲应 4 字节（或 cache line）对齐；长度对齐。
有 cache 的 MCU（Cortex-M7 等）：DMA 写内存后 CPU 读之前要 **invalidate cache**；CPU 写内存后 DMA 读之前要 **clean cache**，否则读到旧数据。

### Q32 浮点数怎么比较？为什么？
**答案**：不能用 `==`，因为二进制浮点无法精确表示大多数小数，运算后有误差。应用 `fabs(a - b) < EPS`。
float 布局：1 位符号 + 8 位指数 + 23 位尾数；double：1+11+52。

## 四、字符串与库函数（8 题）

### Q33 ★★ sizeof 和 strlen 的区别？对数组和指针分别得什么？
**答案**：sizeof 是编译期运算符求字节数；strlen 是运行时函数数到 `\0`（不含）。
```c
char s[] = "abc"; char *p = "abc";
sizeof(s)=4, strlen(s)=3, sizeof(p)=8, strlen(p)=3
```

### Q34 ★ 手写 strcpy。
**答案**：三句要点——① 判空返回 NULL ② 保存 dst 首地址用于返回 ③ `while ((*d++ = *src++) != '\0');` 赋值与判断合一。
完整代码见 **4.2**。

### Q35 ★ 手写 memcpy，考虑内存重叠。
**答案**：核心是判断方向——`d <= s` 正向拷贝；`d > s` 反向拷贝（指针先移到末尾再往前复制），避免源数据被提前覆盖。
完整代码见 **4.3**。

### Q36 ★ 手写 atoi，考虑正负号、空白、非法字符。
**答案**：四个步骤——① 跳过前导空白 ② 处理 '+'/'-' 记符号 ③ 逐位累加 `num = num*10 + (*s - '0')` ④ 遇非数字停止，返回 `sign * num`。
完整代码见 **4.5**。边界：空串/全空白返回 0；溢出未处理（进阶可加 INT_MAX 检查）。

### Q37 ★ 手写字符串查找子串（西门子真题）。
**答案**：双重循环——外层遍历长串起点，内层逐字符比对；needle 全部匹配完（`!*n`）即找到，返回该起点。
复杂度 O(n*m)；KMP 可优化到 O(n+m)。完整代码见 **4.6**。

### Q38 ★ printf 返回值题：
```c
int i = 43;
printf("%d\n", printf("%d", printf("%d", i)));
```
**答案**：输出 **4321**。printf 返回输出的字符数（不含 `\0`）：最内层输出 "43" 返回 2 → 中间输出 "2" 返回 1 → 最外输出 "1"。

### Q39 字符串字面量能不能修改？
**答案**：不能。`char *p = "abc"; p[0] = 'x';` 是未定义行为（字面量在 .rodata 只读段，通常段错误）。
要修改用数组：`char s[] = "abc"; s[0] = 'x';`

### Q40 缓冲区溢出如何防范？
**答案**：用 `snprintf`/`strncpy` 并检查长度、编码时校验边界、编译器栈保护（`-fstack-protector`）、MPU 设置只读/不可执行区、代码审查与静态分析。

## 五、编译与调试（5 题）

### Q41 ★★ 编译四个阶段分别做什么？
**答案**：预处理（展开 include/define、条件编译、删注释）→ 编译（C→汇编）→ 汇编（→目标文件，含符号表）→ 链接（符号解析+重定位，合并静态/动态库）。

### Q42 ★ 头文件为什么要防重复包含？两种写法。
**答案**：防止同一头文件被多次包含导致重复定义。
写法：`#ifndef __X_H__ / #define __X_H__ / ... / #endif` 或 `#pragma once`。

### Q43 静态库和动态库的区别？
**答案**：静态库编译时拷入可执行文件（体积大、更新要重编、嵌入式常用）；动态库运行时加载（体积小、可共享、更新方便，需 OS 支持）。

### Q44 程序跑飞/HardFault 怎么排查？
**答案**：① 读 CFSR/HFSR/BFAR/MMFAR 定位故障类型与地址 ② 分析栈上返回地址或 backtrace ③ 常见原因：空指针、栈溢出、数组越界、野指针、未对齐访问 ④ 手段：断言、栈填充检测、MPU、记录复位原因。

### Q45 ★ GCC 常用参数？-O0 和 -O2 有什么区别（结合 volatile）？
**答案**：`-Wall -Wextra`（警告）、`-g`（调试信息）、`-O0~-O3`/`-Os`（优化等级）、`-I/-L/-l`（路径与库）、`-D`（定义宏）、`-std=c11`。
`-O2` 会做寄存器缓存、循环优化、死代码消除——**这正是必须用 volatile 的原因**：不加 volatile，编译器可能把"主循环里反复读的变量"优化成只读一次，导致永远等不到中断修改。

# 第三部分：易错速查（考前 5 分钟）

| 陷阱 | 记住 |
|---|---|
| `*p++` | 等价 `*(p++)`：先取值，再移动指针 |
| `(*p)++` | 先取值，值加 1 |
| `a[5]` 越界 | 未定义行为，不报错 |
| `char` 符号性 | 平台相关，字节数据用 `uint8_t` |
| 有符号/无符号混合比较 | 有符号转无符号，-10 会变成极大值 |
| `sizeof(数组形参)` | 数组作函数参数退化为指针，sizeof 是指针大小 |
| 字符串字面量赋值 | 只读，改它崩溃 |
| malloc 不检查返回值 | 嵌入式里可能真的返回 NULL |
| `i = i++` | 未定义行为 |
| 位域跨平台 | 位序和分配未定义，协议不用位域 |
| 结构体比较 | 不能用 memcmp（有填充字节） |
| 浮点比较 | 不能 `==`，用误差判断 |
