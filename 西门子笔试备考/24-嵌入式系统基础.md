# 第一部分：嵌入式系统概念

### 1.1 什么是嵌入式系统 ★
**定义**：为特定功能定制、嵌入在设备内部的计算机系统。
**三个特点**：
1. **专用性**：针对特定任务优化（如 ABS 只管刹车）
2. **嵌入性**：隐藏在设备内部，用户感知不到
3. **资源受限**：CPU/内存/功耗有限

**其他特征**：实时性要求、高可靠性、长期无人值守、常运行裸机或 RTOS。

### 1.2 什么是固件（Firmware）★★（真题）
**定义**：固化在硬件非易失存储器（Flash/ROM）中的、直接驱动硬件并提供基本功能的软件。介于硬件和操作系统/应用之间。

**特点**：
1. **固化存储**：烧写在 Flash/ROM 中，掉电不丢失
2. **强硬件相关**：直接操作寄存器、外设，与具体芯片绑定
3. **不可（或少）修改**：出厂后靠 OTA/bootloader 升级，不像应用软件随意安装
4. **可靠性要求高**：跑在无人值守的设备里，出错可能导致设备变砖

**固件包含什么**：启动代码（startup）、硬件初始化、驱动（BSP）、RTOS、中间件、应用逻辑。

**举例**：路由器固件、打印机固件、PLC 固件、手机基带固件、耳机固件、SSD 固件。

**与"软件"的区别**：固件是软件的"最底层部分"，但更强调与硬件的绑定和不可变性。英文 Firmware 由 firm（坚固）+ ware（器件）构成，体现"介于硬件与软件之间"。

### 1.3 ROM / RAM 与各类存储器 ★★（真题）
| 类型 | 掉电 | 可写 | 速度 | 用途 |
|---|---|---|---|---|
| **ROM**（只读存储器） | 不丢失 | 出厂写入，不可改 | 慢 | 老式存固件 |
| **Mask ROM** | 不丢失 | 制造时固化 | 慢 | 大批量低成本产品 |
| **OTP ROM**（一次可编程） | 不丢失 | 只能写一次 | 慢 | 小批量/密钥存储 |
| **EPROM** | 不丢失 | 紫外擦除（已淘汰） | 慢 | 历史 |
| **EEPROM** | 不丢失 | **按字节**可擦写（约 100 万次） | 慢 | 参数、配置、校准数据 |
| **Flash** | 不丢失 | **按扇区/块擦除**后写（约 1 万~10 万次） | 中 | **存代码和常量**（最主要） |
| **SRAM** | 丢失 | 可任意读写 | 快（无需刷新） | **运行时的栈、堆、变量**（MCU 内置） |
| **DRAM** | 丢失 | 可任意读写，需定时刷新 | 较慢 | 大容量内存（外挂 DDR） |
| **FRAM**（铁电） | 不丢失 | 可字节写，擦写近无限（10^12） | 快 | 高频数据记录 |
| **MRAM** | 不丢失 | 可读写，速度快 | 快 | 新兴，高可靠场景 |

**关键区别（考题常问）**：
- **RAM 掉电丢失，ROM/Flash 掉电不丢失**
- **RAM 可随机读写（读写等价），Flash 必须先擦后写且按块擦除**
- **SRAM vs DRAM**：SRAM 用触发器存储（6 管/位），不需要刷新，快但贵、容量小；DRAM 用电容存储（1 管 1 容），需周期性刷新，便宜容量大

**MCU 里的存储布局**：程序存 **Flash**，运行时变量/栈/堆在 **SRAM**，参数存 **EEPROM/Flash 模拟 EEPROM**。

### 1.4 系统构成 ★
| 模块 | 功能 |
|---|---|
| **MCU/MPU** | 核心控制器（Cortex-M / Cortex-A / RISC-V / 8051） |
| **存储器** | Flash（存代码）、SRAM（运行数据）、EEPROM（参数） |
| **外设** | GPIO、UART、SPI、I2C、ADC、PWM、定时器、DMA |
| **传感器/执行器** | 感知与动作 |
| **通信模块** | WiFi/BLE/LoRa/CAN/以太网/4G |
| **电源管理** | LDO/DC-DC、电池管理、低功耗模式 |

### 1.5 MCU vs MPU vs SoC ★
| | MCU（微控制器） | MPU（微处理器） | SoC |
|---|---|---|---|
| 特点 | **片上集成** CPU+Flash+RAM+外设 | 只有 CPU，内存外设需外接 | 集成更多（含 GPU/NPU/多核） |
| 例子 | STM32、ESP32、nRF52 | i.MX、AM335x | 树莓派 SoC、骁龙 |
| 系统 | 通常裸机/RTOS | Linux/Android | Linux/Android |
| 内存 | 内置 KB 级 | 外挂 DDR（MB~GB） | 外挂 DDR |
| MMU | 通常**无**（部分有 MPU 内存保护） | **有** | 有 |

**关键区别**：**有没有 MMU** 决定了能不能跑 Linux（Linux 需要虚拟内存）。

### 1.6 ARM Cortex 系列 ★★
| 系列 | 架构 | 定位 | 特点 |
|---|---|---|---|
| **Cortex-M0/M0+** | ARMv6-M | 超低功耗 MCU | 指令少（Thumb 子集）、无位带、无硬件除法 |
| **Cortex-M3** | ARMv7-M | 主流 MCU | 有硬件除法、位带、更强中断 |
| **Cortex-M4** | ARMv7E-M | 带 DSP 的 MCU | M3 + **DSP 指令 + 可选 FPU**（单精度） |
| **Cortex-M7** | ARMv7E-M | 高性能 MCU | 双发射、指令/数据 cache、更高主频 |
| **Cortex-M33** | ARMv8-M | 安全 MCU | TrustZone 安全扩展 |
| **Cortex-A**（A7/A53/A72…） | ARMv7-A/ARMv8-A | 应用处理器 | **有 MMU**，跑 Linux/Android |
| **Cortex-R** | ARMv7-R | 实时 | 高可靠、硬实时（汽车/存储控制器） |

**M 系列寄存器组** ★：
- **R0-R12**：通用寄存器
- **R13 = SP**：栈指针（Cortex-M 有 **MSP 主栈** 和 **PSP 进程栈**两个）
- **R14 = LR**：链接寄存器（存返回地址）
- **R15 = PC**：程序计数器
- **特殊寄存器**：
  - **xPSR**：程序状态（含标志位、IPSR 中断号）
  - **PRIMASK**：置 1 屏蔽所有可屏蔽中断
  - **FAULTMASK**：置 1 屏蔽所有异常（除 NMI）
  - **BASEPRI**：屏蔽优先级数值 ≥ 该值的中断（**FreeRTOS 临界区用的就是它**）
  - **CONTROL**：控制使用 MSP/PSP、特权/非特权态

# 第二部分：启动流程 ★★★

### 2.1 从上电到 main（必须能讲）★
```
① 上电/复位
   ↓
② 从固定地址取初始 SP 和复位向量
   - Cortex-M：地址 0x00000000 处是**中断向量表**
   - 第 0 项 = 初始 SP 值
   - 第 1 项 = Reset_Handler 地址
   ↓
③ 执行 Reset_Handler（启动代码，startup_xxx.s）
   - 初始化时钟（有些先跑内部 RC 再切外部晶振 + PLL）
   - **拷贝 .data 段**从 Flash 到 RAM（已初始化的全局/静态变量）
   - **清零 .bss 段**（未初始化的全局/静态变量）
   - 调用 SystemInit()（芯片厂商提供的时钟/外设初始化）
   - 调用 __libc_init_array（C++ 全局对象构造）
   ↓
④ 跳转到 main()
```

### 2.2 中断向量表 ★★
存放在 Flash 起始处（可重定位到 RAM 以支持动态改）。
- 第 0 项：**初始 SP 值**（不是函数地址！）
- 第 1 项：**Reset_Handler** 地址
- 第 2 项：NMI
- 第 3 项：HardFault
- 第 4-10 项：MemManage / BusFault / UsageFault / 保留
- 第 11 项：SVCall
- 第 12-13 项：DebugMon / 保留
- 第 14 项：**PendSV**
- 第 15 项：**SysTick**
- 之后：各外设中断（IRQ0, IRQ1, ...）

**重定位**：`SCB->VTOR = 新地址`（bootloader 跳转 app 时必须做）。

### 2.3 Bootloader 与 OTA ★★
**为什么需要**：产品出厂后要能升级固件（不能拆机接线）。
**典型分区**：
```
+-------------+
| Bootloader  |  ← 上电先跑，负责升级/跳转
+-------------+
| 应用区 A     |  ← 当前运行
+-------------+
| 备份区 B     |  ← 新固件先下到这里
+-------------+
| 参数区       |  ← 版本号、升级标志、CRC
+-------------+
```
**升级流程**：
1. 收到新固件 → 写入备份区 B
2. 校验（CRC/签名）通过 → 置升级标志
3. 重启 → bootloader 看到标志 → 把 B 拷到 A（或直接跳到 B）
4. 校验 A 有效 → 跳转；无效 → 回滚到旧版本

**跳转 app 的关键步骤** ★：
1. 关闭所有中断、关闭 SysTick
2. 检查 app 向量表前两项合法性（SP 在 RAM 范围、Reset 地址在 Flash 范围）
3. 设置 `SCB->VTOR = APP_BASE`
4. 重设 MSP 为 app 的初始 SP：`__set_MSP(*(uint32_t*)APP_BASE)`
5. 跳到 app 的 Reset_Handler：`((void(*)(void))(*(uint32_t*)(APP_BASE+4)))()`

# 第三部分：中断与 NVIC ★★★

### 3.1 NVIC（嵌套向量中断控制器）★★
- 管理所有中断的使能、优先级、挂起、清除
- **支持中断嵌套**：高优先级中断可打断低优先级
- Cortex-M0/M0+：2 位优先级（4 级）；M3/M4：3~4 位（8~16 级）；M7：4~8 位
- **硬件自动保存/恢复现场**（R0-R3/R12/LR/PC/xPSR），比软件快得多

### 3.2 优先级机制 ★★★
**关键：数值越小优先级越高**（Cortex-M 与某些架构相反，容易记错）

STM32 用**优先级分组**把每个中断优先级字段分成两部分：
| 分组 | 抢占优先级位数 | 响应（子）优先级位数 |
|---|---|---|
| Group 0 | 0 | 4 |
| Group 1 | 1 | 3 |
| Group 2 | 2 | 2 |
| Group 3 | 3 | 1 |
| Group 4 | 4 | 0 |

- **抢占优先级**：决定能否打断其他中断（**抢占**）
- **响应优先级**：抢占优先级相同时，同时到达谁先执行；**不能嵌套**
- 设置：`NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2)` + `HAL_NVIC_SetPriority(IRQn, preempt, sub)`

**举例（Group 2，2 位抢占 + 2 位子）**：
中断 A（抢占 1，子 0）可以打断中断 B（抢占 2，子 0）；
中断 C（抢占 1，子 0）不能打断 A（抢占相同，不能嵌套），但同时到达时子优先级高的先跑。

### 3.3 系统异常（Cortex-M）★
| 异常 | 编号 | 说明 |
|---|---|---|
| **Reset** | 1 | 上电/复位 |
| **NMI** | 2 | 不可屏蔽中断 |
| **HardFault** | 3 | 硬件错误（所有 fault 的兜底） |
| MemManage | 4 | 内存保护错误（MPU） |
| BusFault | 5 | 总线错误（访问非法地址） |
| UsageFault | 6 | 用法错误（未定义指令、除零） |
| **SVCall** | 11 | 系统调用（触发 OS 服务） |
| **PendSV** | 14 | 可挂起系统服务（**RTOS 上下文切换用**） |
| **SysTick** | 15 | 系统节拍定时器 |

**优先级**：`NVIC_SetPriority(SysTick_IRQn, 15)` 等——RTOS 通常把 PendSV 和 SysTick 设为**最低优先级**。

### 3.4 中断处理流程 ★
```
外部事件（如串口收到数据）
  ↓ 硬件置中断挂起位
NVIC 判断优先级（高于当前 → 抢占）
  ↓
CPU 自动保存现场（压栈 R0-R3,R12,LR,PC,xPSR）
  ↓
查向量表，跳到 ISR
  ↓
执行 ISR（清中断标志！）
  ↓ 硬件自动恢复现场
继续原程序
```

**没清中断标志的后果**：中断返回后立即再次进入（中断风暴），系统卡死。

### 3.5 HardFault 调试 ★★（场景题）
**故障状态寄存器**：
| 寄存器 | 查什么 |
|---|---|
| **CFSR**（Configurable Fault Status） | 具体故障：MMFSR（内存）+ BFSR（总线）+ UFSR（用法） |
| **HFSR**（HardFault Status） | 是哪种 fault 升级来的（FORCED 位） |
| **BFAR** | 总线错误地址（BFSR 的 BFARVALID 置位时有效） |
| **MMFAR** | 内存保护错误地址 |

**常见原因**：空指针解引用、数组越界、栈溢出、野指针、未对齐访问、除零、跳转到非法地址、栈被写坏导致返回地址错误。

**排查手段**：断言、栈填充检测、MPU、记录复位原因、用调试器看异常时的栈帧（HardFault 里保存的 PC 就是出错地址）。

# 第四部分：DMA ★★★

### 4.1 什么是 DMA ★
**Direct Memory Access**：外设与内存之间**直接搬运数据，不经过 CPU**。

**工作流程**：
1. CPU 配置 DMA：源地址、目的地址、传输长度、触发源（外设请求）、传输模式
2. 使能 DMA → 外设产生请求时 DMA 自动搬运
3. 传输完成 → 产生中断/置标志 → CPU 处理数据

**优点**：解放 CPU（大数据量搬运时 CPU 可做其他事）、速度快、适合连续数据流。
**缺点**：配置复杂、占用总线带宽、有 cache 一致性问题。

### 4.2 DMA 的关键配置项 ★
| 配置 | 说明 |
|---|---|
| **方向** | 外设→内存（如 ADC/UART RX）、内存→外设（UART TX）、内存→内存 |
| **地址自增** | 内存地址通常自增，外设地址通常固定（同一个数据寄存器） |
| **数据宽度** | 8/16/32 位（源和目的要匹配） |
| **传输数量** | 搬多少次 |
| **触发源** | 哪个外设请求（如 USART1_RX、ADC1、TIM2_CC1） |
| **循环模式（Circular）** | 传完自动重新开始（环形缓冲，**接收连续数据必备**） |
| **传输完成中断** | 搬完通知 CPU |
| **双缓冲（Double Buffer）** | 一块传的时候另一块可被 CPU 处理（无间断） |

### 4.3 DMA 的经典用法 ★★
#### 串口 + DMA 接收（不定长数据）
```c
// 1. DMA 循环模式接收，永远不停止
HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_buf, BUF_SIZE);

// 2. 空闲中断（IDLE）触发 → 表示这一帧收完了
void USART1_IRQHandler(void) {
    if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_IDLE)) {
        __HAL_UART_CLEAR_IDLEFLAG(&huart1);
        // 读取 DMA 当前剩余计数，算出收到多少字节
        uint16_t cnt = BUF_SIZE - __HAL_DMA_GET_COUNTER(huart1.hdmarx);
        process_data(rx_buf, cnt);
    }
}
```
**要点**：**DMA + 空闲中断**是嵌入式接收不定长数据的最佳实践（不用每字节进中断）。

#### ADC + DMA 多通道采样
ADC 扫描多个通道 → 每次转换完成触发 DMA 搬到数组 → 一轮结束后中断处理。CPU 完全不参与搬运。

### 4.4 Cache 一致性问题 ★★★（有 cache 的 MCU 必考）
**问题**：CPU 有 cache，DMA 直接读写内存（不经过 cache）→ 两边数据不一致。
- CPU 写数据在 cache 里未落盘，DMA 读内存读到旧数据
- DMA 写内存后，CPU 读 cache 里的旧数据

**解决**：
| 场景 | 操作 |
|---|---|
| CPU 写完 → DMA 读（发送） | **Clean**（把 cache 刷回内存） |
| DMA 写完 → CPU 读（接收） | **Invalidate**（让 cache 失效，强制从内存读） |
| 缓冲区 | 按 **cache line**（Cortex-M7 通常 32 字节）**对齐**，避免与相邻变量共享 cache line 被误刷 |

**免 cache 区域**：把 DMA 缓冲区放到**非 cache 区域**（MPU 配置），彻底避免一致性问题。

# 第五部分：GPIO 与常见外设

### 5.1 GPIO 八种模式 ★★★（STM32 高频）
| 模式 | 说明 | 用途 |
|---|---|---|
| **浮空输入** | 高阻态 | 外部已有明确驱动的信号 |
| **上拉输入** | 内部上拉 | 按键（默认高） |
| **下拉输入** | 内部下拉 | 按键（默认低） |
| **模拟输入** | 断开数字电路 | **ADC 采集** |
| **推挽输出** | 能输出高/低 | LED、普通数字输出、UART TX |
| **开漏输出** | 只能拉低，高靠外部上拉 | **I2C**、电平转换、多器件共线 |
| **复用推挽** | 由外设控制 | USART TX、SPI SCK/MOSI |
| **复用开漏** | 由外设控制，开漏 | I2C SDA/SCL |

**推挽 vs 开漏（必问）**：
- 推挽：内部上下管，能主动输出高和低，**驱动能力强**，但多器件共线时会冲突（一个要输出高一个要输出低 → 大电流烧毁）
- 开漏：只有下管，只能拉低；高电平靠**外部上拉**；**可多器件共线**（线与，不会短路）

### 5.2 GPIO 中断配置步骤 ★
1. 配置 GPIO 为输入模式
2. 使能 SYSCFG 时钟，配置 `SYSCFG_EXTICR` 选择哪个端口映射到 EXTI 线
3. 配置 `EXTI_IMR`（中断屏蔽）、`EXTI_RTSR`（上升沿）/`EXTI_FTSR`（下降沿）
4. 在 NVIC 中使能对应 EXTI 中断并设置优先级
5. 在 ISR 中**清除 EXTI 挂起位**

### 5.3 定时器 ★★
**用途**：定时中断、PWM 输出、输入捕获（测频率/脉宽）、编码器接口、DMA 触发。

**基本定时器配置**：
```
定时时间 = (PSC + 1) × (ARR + 1) / 时钟频率
例：72MHz，PSC=71（72分频→1MHz），ARR=999 → 定时 = 1MHz/1000 = 1ms
```
| 寄存器 | 作用 |
|---|---|
| PSC（预分频） | 把时钟分频后给计数器 |
| ARR（自动重装载） | 计数值上限，到上限产生更新事件 |
| CCR（捕获/比较） | PWM 占空比 / 捕获值 |
| CNT | 当前计数值 |

**PWM 输出**：占空比 = CCR / (ARR+1)。

**输入捕获测频率**：两次捕获的时间差 → 频率 = 1/时间差。
**输入捕获测占空比**：高电平时间 / 周期。

### 5.4 ADC 外设配置（原理与换算见 `21-硬件常识与电路.md` 3.1）
| 配置项 | 说明 |
|---|---|
| **单次 / 连续转换** | 转一次停 / 转完立即开始下一次 |
| **扫描模式** | 一次转换多个通道（配 DMA 取结果） |
| **DMA** | 自动搬运转换结果，CPU 不参与 |
| **注入通道** | 可打断规则通道的高优先级转换（用于紧急采样） |
| **校准** | 启动前应执行 ADC 校准（消除内部电容失配误差） |
| **外部触发** | 可由定时器触发采样（保证采样间隔精确） |

**提高精度的工程手段**：过采样累加平均、参考电压稳定（用外部基准）、避开数字噪声（模拟地与数字地分开）、信号源阻抗匹配（加缓冲运放）、输入端加 RC 滤波。

### 5.5 看门狗 ★★
| 类型 | 时钟源 | 特点 |
|---|---|---|
| **IWDG**（独立看门狗） | 独立内部 RC（LSI ~32kHz） | 主时钟坏了也能工作，**最可靠**；喂狗时间范围 10ms~16s |
| **WWDG**（窗口看门狗） | 由 PCLK 分频 | **必须在时间窗口内喂**（喂太早也复位），能检测程序跑飞后"过快返回" |

**为什么要有窗口看门狗**：普通看门狗只能检测"程序卡死"；若程序跑飞后恰好落在喂狗语句上，会被"假喂"骗过。窗口看门狗要求喂狗时间在窗口内，跑飞导致的过早喂狗会触发复位。

### 5.6 复位原因记录（实战技巧）
在启动代码中读 `RCC->CSR` 的复位标志，记录到备份寄存器/非易失存储，用于现场诊断（是上电复位、看门狗复位、软件复位还是掉电复位）。

# 第六部分：低功耗 ★★

### 6.1 STM32 三种低功耗模式 ★★
| 模式 | CPU | 时钟 | SRAM/寄存器 | 唤醒源 | 典型功耗 |
|---|---|---|---|---|---|
| **Sleep（睡眠）** | 停止 | 运行 | 保持 | **任意中断** | mA 级 |
| **Stop（停止）** | 停止 | 全部停止（保留 LSI/LSE） | 保持 | **EXTI 线**（外部中断） | 10μA 级 |
| **Standby（待机）** | 停止 | 全部停止 | **丢失**（除备份域） | WKUP 引脚 / RTC / IWDG | 2μA 级 |

**唤醒后**：
- Sleep：从停止处继续执行
- Stop：继续执行（时钟需重新配置）
- Standby：**相当于复位**，从启动代码重新开始（所以要用备份寄存器保存状态）

### 6.2 低功耗设计要点 ★
1. **降低主频与电压**：功耗 ≈ f × V²（降频降压最有效）
2. **关闭不用的外设时钟**（`__HAL_RCC_XXX_CLK_DISABLE()`）
3. **未用引脚配置为模拟输入或输出固定电平**（悬空会漏电）
4. **尽量用中断唤醒**而非轮询
5. **RTOS 的 Tickless 模式**：空闲时不产生周期 tick，深度睡眠
6. **DMA 代替 CPU 搬运**，让 CPU 多睡
7. 外部器件也要管（传感器待机模式、上拉电阻不必要就断开）

### 6.3 功耗估算例子
```
平均功耗 = 运行时间占比 × 运行电流 + 睡眠时间占比 × 睡眠电流
例：1% 时间运行（10mA），99% 睡眠（10μA）
   = 0.01 × 10mA + 0.99 × 0.01mA ≈ 0.11mA
```
→ **占空比运行是低功耗的核心思想**。

# 第八部分：题目（30 题，答案已给）

## 概念

### Q1 ★ 什么是嵌入式系统？有哪些特点？
**答案**：为特定功能定制、嵌入设备内部的计算机系统。
特点：专用性（针对特定任务优化）、嵌入性（用户无感知）、资源受限（CPU/内存/功耗）、实时性要求、高可靠性、常跑裸机或 RTOS。

### Q2 ★★ MCU 和 MPU 的核心区别是什么？为什么 MCU 通常跑不了 Linux？
**答案**：MCU 片上集成 CPU+Flash+RAM+外设，资源小；MPU 只有 CPU，内存外设外接，资源大。
**核心区别是有没有 MMU**：Linux 依赖虚拟内存和进程隔离，需要 MMU；绝大多数 MCU 没有 MMU（只有 MPU 内存保护单元），所以跑不了标准 Linux。
（例外：Cortex-A 的 SoC 属 MPU 类；有的 MCU 有 MMU 可跑 uClinux 之类的无 MMU 版本）

### Q3 ★ Cortex-M3 和 M4 的区别？M4 的 FPU 有什么用？
**答案**：M4 = M3 + DSP 指令集 + 可选单精度 FPU。
FPU 的作用：硬件执行浮点运算（乘加等），比软件浮点快几十倍，适合电机控制（FOC）、音频处理、传感器融合。

### Q4 ★ Cortex-M 的栈指针有几个？分别什么时候用？
**答案**：两个——**MSP**（主栈指针）和 **PSP**（进程栈指针）。
复位后默认用 MSP；中断/异常处理**总是用 MSP**；PSP 用于 RTOS 中任务各自的栈（通过 CONTROL 寄存器切换）。
这样设计让每个任务有独立栈，而中断使用统一的主栈，节省 RAM 且切换快。

## 启动流程

### Q5 ★★★ 从上电到 main 函数，经历了什么？
**答案**：见 2.1。关键五步：
① 上电复位 → ② 从地址 0 取初始 SP（第 0 项）和 Reset_Handler 地址（第 1 项）→ ③ Reset_Handler 里初始化时钟、**拷贝 .data 到 RAM、清零 .bss** → ④ 调用 SystemInit 和 C++ 全局构造 → ⑤ 跳转 main。

### Q6 ★★ 中断向量表的前两项是什么？为什么第 0 项不是函数地址？
**答案**：第 0 项 = **初始栈指针 SP 的值**；第 1 项 = **Reset_Handler 的地址**。
第 0 项是 SP 值而不是函数地址，是因为上电后 CPU 需要立刻有一个有效的栈才能开始工作（后续任何中断/函数调用都要压栈）。这是 ARM 的硬件约定。

### Q7 ★★ .data 和 .bss 在启动时分别怎么处理？为什么？
**答案**：
- **.data**（已初始化的全局/静态变量）：从 **Flash 拷贝到 RAM**，因为变量要可写、掉电不保存，初值存在 Flash
- **.bss**（未初始化的全局/静态变量）：**清零**，C 语言标准要求未初始化全局变量为 0
两者都不在 Flash 里存实际数据（.bss 完全不占 Flash 空间），只有 .data 的初值占 Flash。

### Q8 ★★ Bootloader 跳转到应用程序需要做哪些事？
**答案**：① 关闭所有中断和 SysTick ② 检查 app 向量表合法性（SP 在 RAM 范围内、Reset 地址在 Flash 范围内）③ 设置 `SCB->VTOR = APP_BASE`（重定位中断向量表）④ 设置 MSP 为 app 的初始栈顶 ⑤ 跳到 app 的 Reset_Handler。
**漏掉 ③ 会导致 app 里的中断全部跳错**（还是进 bootloader 的向量表）。

### Q9 OTA 升级怎么设计才安全？
**答案**：A/B 双分区（新固件写备份区，校验通过才切换）、**CRC/数字签名校验**（防止传输错误和恶意固件）、**升级标志 + 回滚机制**（新固件启动失败自动回滚旧版）、断电保护（写标志要原子）、版本号管理、防降级（可选）。

## 中断与 NVIC

### Q10 ★★★ NVIC 的优先级数值越大还是越小越高？
**答案**：**数值越小，优先级越高**（Cortex-M 的约定）。这与某些架构相反，是常见记错点。
所以最高优先级是 0，最低是（2^n - 1）。

### Q11 ★★★ 抢占优先级和响应（子）优先级有什么区别？
**答案**：
- **抢占优先级**：决定能否**打断**正在执行的中断（抢占/嵌套）
- **响应优先级**：抢占优先级**相同时**，同时到达的两个中断谁先执行；**不能嵌套**（执行中不会被同抢占级的打断）
STM32 用 `NVIC_PriorityGroupConfig` 决定两者各占几位。

### Q12 ★★ 中断处理为什么不能太长？中断里不能做什么？
**答案**：会屏蔽同级和低优先级中断，增加响应延迟，可能丢数据/丢中断，破坏实时性；中断上下文不能睡眠。
不能做：printf（慢、不可重入）、延时/sleep、malloc（不可重入且耗时不确定）、浮点运算（若不保存 FPU 上下文）、调用可能阻塞的 API、长时间循环。

### Q13 ★ ISR 里忘记清中断标志会怎样？
**答案**：中断返回后，挂起位仍然是 1 → 立即再次进入同一个 ISR → **中断风暴**，CPU 100% 卡在中断里，主程序无法运行。

### Q14 ★★★ HardFault 怎么排查？
**答案**：读故障寄存器——**CFSR**（具体类型：内存/总线/用法）、**HFSR**（哪种 fault 升级来的）、**BFAR/MMFAR**（出错地址）。
常见原因：空指针、数组越界、栈溢出、野指针、未对齐访问、跳转到非法地址。
进一步：用调试器看 HardFault 时压栈的 PC（就是出错指令地址），或用栈回溯、断言、MPU、栈填充检测。

### Q15 ★ 什么是 PendSV？为什么 RTOS 用它做上下文切换？
**答案**：PendSV 是可挂起的系统异常（编号 14）。
RTOS 把它设为**最低优先级**，这样它只在所有其他中断处理完后才执行——保证上下文切换不会打断任何中断，在最安全的时刻进行。同时可以"挂起而不立即执行"，实现延后切换（比如同一次操作里多次请求切换只切一次）。

### Q16 ★ SysTick 的作用？RTOS 用它做什么？
**答案**：SysTick 是 Cortex-M 内置的系统节拍定时器（24 位递减计数）。
RTOS 用它产生周期性 tick 中断：① 任务延时计时 ② 同优先级任务时间片轮转 ③ 软件定时器。`configTICK_RATE_HZ` 通常设 1000（1ms）。

## DMA

### Q17 ★★★ DMA 是什么？为什么快？CPU 在期间做什么？
**答案**：DMA（直接存储器访问）让外设与内存直接搬运数据，不经过 CPU 逐字节搬运。
快的原因：硬件状态机搬运，不需要 CPU 取指-译码-执行，也不占用 CPU 时间。
期间 CPU 可以执行其他任务，DMA 完成后用中断通知。

### Q18 ★★ DMA 的关键配置项有哪些？
**答案**：方向（外设→内存/内存→外设/内存→内存）、源/目的地址、**地址是否自增**（内存通常自增，外设固定）、数据宽度（8/16/32 位，两边要匹配）、传输数量、**触发源**（哪个外设请求）、循环模式、传输完成中断、优先级（多通道时）。

### Q19 ★★★ 用 DMA 接收串口的不定长数据，怎么实现？
**答案**：**DMA 循环模式 + 串口空闲中断（IDLE）**。
① DMA 配置为循环模式接收，始终运行
② 串口空闲中断触发时（一帧传输结束、总线变空闲），读 DMA 剩余计数算出本次收到多少字节
③ 处理数据
优点：不用每收一个字节进一次中断，CPU 几乎零负担，也不丢数据。

### Q20 ★★★ 有 Cache 的 MCU 用 DMA 要注意什么？
**答案**：**Cache 一致性**问题——CPU 通过 cache 读写，DMA 直接读写内存，两者可能不一致。
- CPU 写后 DMA 读（发送）：要 **Clean**（把 cache 写回内存）
- DMA 写后 CPU 读（接收）：要 **Invalidate**（让 cache 失效，强制从内存读）
- 缓冲区按 **cache line 对齐**（避免与相邻变量共用 cache line 被误刷）
- 或把 DMA 缓冲区配置到**非 cache 区域**（MPU）彻底避免

### Q21 DMA 和中断传递数据的区别？
**答案**：中断方式是每个字节/每次事件都进中断，CPU 频繁打断，高波特率时会丢数据；DMA 是硬件批量搬运，只在"传输完成"或"半传输"时通知一次，CPU 开销极小。
结论：低速少量用中断，高速大量用 DMA。

## GPIO 与外设

### Q22 ★★★ STM32 的 GPIO 有哪几种模式？推挽和开漏的区别？
**答案**：浮空输入、上拉输入、下拉输入、模拟输入、推挽输出、开漏输出、复用推挽、复用开漏（8 种）。
推挽：内部上下管，能主动输出高/低，驱动能力强，但多器件共线会冲突（短路大电流）。
开漏：只有下管，只能拉低，高靠外部上拉，**可多器件共线**（线与）——I2C 必须用开漏。

### Q23 ★ 什么时候用开漏输出？
**答案**：① **I2C 的 SDA/SCL**（多主多从，需要线与）② 需要电平转换（上拉到不同电压）③ 多个器件共享一根信号线（如中断线、总线仲裁）④ 驱动强上拉/大电流负载（外加功率管）。

### Q24 ★★ GPIO 外部中断怎么配置？
**答案**：① GPIO 配置为输入 ② 使能 SYSCFG 时钟，配置 EXTICR 把该端口映射到 EXTI 线 ③ 配置 EXTI 的屏蔽位和触发边沿（上升/下降/双边）④ 在 NVIC 中使能 EXTI 中断并设置优先级 ⑤ 在 ISR 中**清除 EXTI 挂起位**（否则反复进中断）。

### Q25 ★★ 定时器怎么配置出 1ms 定时中断？公式？
**答案**：`定时时间 = (PSC+1) × (ARR+1) / 时钟频率`
例：72MHz，PSC=71（分频到 1MHz），ARR=999：1MHz × (999+1) = 1ms。

### Q26 ★ PWM 的频率和占空比由什么决定？怎么用 PWM 调光/调速？
**答案**：频率 = 时钟 / ((PSC+1) × (ARR+1))；占空比 = CCR / (ARR+1)。
调光/调速通过改变 CCR 改变占空比，从而改变平均功率。LED 用视觉暂留（频率 >100Hz），电机用平均电压（频率 10~20kHz 避开噪音和开关损耗）。

### Q27 ★ 输入捕获能测什么？怎么测频率和占空比？
**答案**：可测信号频率、周期、脉宽、占空比、编码器位置。
测频率：两次捕获的时间差 → f = 1/ΔT（或固定时间内数脉冲个数）。
测占空比：捕获上升沿和下降沿，高电平时间 / 整个周期。

### Q28 ★★ 独立看门狗和窗口看门狗的区别？
**答案**：IWDG 用独立内部 RC 时钟，主时钟坏了也能工作，用于检测程序跑飞/卡死；WWDG 用主时钟分频，**必须在时间窗口内喂狗**（喂太早也复位），用于检测程序执行时间异常（如跑飞后过快返回）。
WWDG 能防"假喂狗"，IWDG 更独立可靠，实际常两者都用。

### Q29 ★★ STM32 三种低功耗模式的区别？
**答案**：
- Sleep：CPU 停，时钟运行，SRAM 保持，任意中断唤醒，mA 级
- Stop：时钟全停，SRAM 保持，EXTI 唤醒，10μA 级
- Standby：时钟全停，SRAM 丢失（仅备份域保留），WKUP/RTC 唤醒，唤醒后相当于复位，2μA 级

### Q30 ★★ 低功耗设计有哪些手段？
**答案**：① 降主频降压（功耗 ∝ f·V²）② 关闭不用外设的时钟 ③ 未用引脚配为模拟输入或固定电平（悬空漏电）④ 用中断唤醒代替轮询 ⑤ DMA 搬运代替 CPU ⑥ RTOS Tickless 模式 ⑦ 占空比运行（大部分时间睡眠）⑧ 外部器件也要待机（传感器、上拉电阻）。

# 第九部分：易错速查

| 陷阱 | 记住 |
|---|---|
| 中断优先级 | **数值越小优先级越高** |
| 向量表第 0 项 | 是 **SP 值**，不是函数地址 |
| .bss | 不占 Flash，启动时清零 |
| .data | 初值存 Flash，启动时拷到 RAM |
| Bootloader 跳转 | 必须设 `SCB->VTOR` |
| ISR 没清标志 | 中断风暴 |
| PendSV | 最低优先级，RTOS 上下文切换 |
| DMA + Cache | clean（发送前）/ invalidate（接收后） |
| I2C 必须 | 开漏输出 + 上拉 |
| 窗口看门狗 | 喂太早也复位 |
| Standby | 唤醒等于复位，SRAM 丢失 |
| 定时公式 | (PSC+1)×(ARR+1)/f |
