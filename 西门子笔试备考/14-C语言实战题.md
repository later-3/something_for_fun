# 第一部分：输出预测题（20 题）

## Q1 指针与数组基础
```c
int a[5] = {1,2,3,4,5};
int *p = a;
printf("%d %d\n", *(p+2), *p+2);
```
<details><summary>答案</summary>

输出：**`3 3`**

`*(p+2)` = a[2] = 3；`*p+2` = (*p)+2 = 1+2 = 3。
**陷阱**：`*p+2` 不加括号，`*` 优先级高于 `+`，先解引用再加 2。
</details>

## Q2 sizeof 与数组退化
```c
void f(int a[]) { printf("%d\n", (int)sizeof(a)); }
int main(void) {
    int a[10];
    printf("%d\n", (int)sizeof(a));
    f(a);
}
```
<details><summary>答案</summary>

输出：**`40`** 然后 **`8`**（64 位系统；32 位系统第二个是 4）

**陷阱**：数组作为函数参数会**退化为指针**，`sizeof(a)` 在函数内是指针大小。
这是最高频的 sizeof 陷阱题。
</details>

## Q3 字符数组 vs 字符指针
```c
char s1[] = "hello";
char *s2 = "hello";
s1[0] = 'H';
s2[0] = 'H';   // 这一行会怎样？
```
<details><summary>答案</summary>

`s1[0] = 'H'` **正常**，s1 变成 "Hello"（栈上数组，可写）。
`s2[0] = 'H'` **未定义行为**，通常**段错误崩溃**（字符串字面量在 .rodata 只读段）。

**考点**：数组是"拷贝一份到栈上"，指针是指"指向只读区的那个字符串"。
**正确改法**：`char b[] = "hello";`
</details>

## Q4 有符号 char
```c
char c = 0xFF;
unsigned char uc = 0xFF;
printf("%d %d\n", c, uc);
```
<details><summary>答案</summary>

输出：**`-1 255`**

**原因**：`char` 在 x86/ARM 上默认**有符号**（-128~127），0xFF 被解释为 -1；`unsigned char` 是 0~255。
**工程影响**：处理字节数据（协议解析、Flash 内容）必须用 `uint8_t`/`unsigned char`。
</details>

## Q5 整数除法与类型转换
```c
printf("%d %f %f\n", 5/2, 5.0/2, (float)5/2);
```
<details><summary>答案</summary>

输出：**`2 2.500000 2.500000`**

**陷阱**：整数除法截断。`5/2` = 2（不是 2.5）。
`5.0/2` 因为 5.0 是 double，整型 2 被提升为 double。
</details>

## Q6 移位与符号
```c
int neg = -8;
unsigned uneg = 0xFFFFFFF8u;
printf("%d 0x%X\n", neg >> 1, uneg >> 1);
```
<details><summary>答案</summary>

输出：**`-4 0x7FFFFFFC`**

**考点**：
- 有符号右移：算术右移（高位补符号位），-8>>1 = -4
- 无符号右移：逻辑右移（高位补 0）
- **标准未规定**有符号右移是算术还是逻辑，但所有主流实现都是算术右移
</details>

## Q7 短路求值
```c
int i = 0;
if (i != 0 && 10/i > 1) printf("A");
else printf("B");
```
<details><summary>答案</summary>

输出：**`B`**

`i != 0` 为假 → `&&` **短路**，后面的 `10/i` 不执行 → 不会除零。
**考点**：`&&` 和 `||` 有短路特性，这是防除零的常用写法。
</details>

## Q8 运算符优先级
```c
int a = 2, b = 3;
printf("%d %d\n", a + b << 1, a + (b << 1));
```
<details><summary>答案</summary>

输出：**`10 8`**

- `a + b << 1`：`+` 优先级高于 `<<`，所以是 `(2+3) << 1` = `5 << 1` = 10
- `a + (b << 1)`：`2 + 6` = 8

**陷阱**：很多人以为先移位。**移位优先级低于加减**（比关系运算高，比其他算术低）。
</details>

## Q9 位运算
```c
printf("%d %d %d %d\n", 5&3, 5|3, 5^3, ~5);
```
<details><summary>答案</summary>

输出：**`1 7 6 -6`**

- `5&3` = `101 & 011` = `001` = 1
- `5|3` = `101 | 011` = `111` = 7
- `5^3` = `101 ^ 011` = `110` = 6
- `~5` = `~00000101` = `11111010`（补码）= **-6**

**考点**：`~` 是对补码取反，不是"加负号"。
</details>

## Q10 逗号表达式
```c
int x = (1, 2, 3);
printf("%d\n", x);
```
<details><summary>答案</summary>

输出：**`3`**

逗号表达式从左到右依次求值，**整体结果是最后一个**（3）。

**陷阱**：`int x = 1, 2, 3;` 是完全不同的东西（声明三个变量，编译错误）。
</details>

## Q11 for 循环中的逗号
```c
int i, j;
for (i = 0, j = 10; i < j; i++, j--) ;
```

<details><summary>答案</summary>

输出：**`5 5`**

i 从 0 递增、j 从 10 递减，每轮各走 1，5 轮后 i==j==5，条件 `i<j` 不成立退出。
</details>

## Q12 指针相减
```c
int arr[5] = {1,2,3,4,5};
printf("%td\n", &arr[4] - &arr[1]);
```
<details><summary>答案</summary>

输出：**`3`**

指针相减得到的是**元素个数**，不是字节数。（字节数要强转成 `char*` 再减：`(char*)&arr[4] - (char*)&arr[1]` = 12）
</details>

## Q13 结构体赋值（浅拷贝）
```c
struct S { int a; char b[8]; } s1 = {1, "abc"}, s2;
s2 = s1;
s2.a = 99;
printf("%d %d %s %s\n", s1.a, s2.a, s1.b, s2.b);
```
<details><summary>答案</summary>

输出：**`1 99 abc abc`**

结构体赋值是**逐成员拷贝**（值语义）。`s2 = s1` 后两者独立，改 s2.a 不影响 s1.a。
**但注意**：如果成员是**指针**，则拷贝的是指针值（浅拷贝），两个结构体的指针指向同一内存 → 这就是"浅拷贝陷阱"。
</details>

## Q14 三种字符串初始化
```c
char c1[] = "abc";
char c2[10] = "abc";
char c3[3] = {'a','b','c'};
printf("%zu %zu %zu %zu %d\n", sizeof c1, sizeof c2, sizeof c3, strlen(c1), c2[5]);
```
<details><summary>答案</summary>

输出：**`4 10 3 3 0`**

- `c1` = 4（'a','b','c','\0'）
- `c2` = 10（声明大小，未用部分补 0）
- `c3` = 3（**没有 `\0`！** 这是字符数组不是字符串，`strlen(c3)` 是 UB）
- `c2[5]` = 0（未初始化部分被零初始化）

**考点**：`char c3[3] = {'a','b','c'}` 不是字符串，用 `strlen`/`printf("%s")` 会越过数组继续读，直到碰到 0。
</details>

## Q15 浮点数比较
```c
float f = 0.1f;
double d = 0.1;
printf("%d %d\n", f == 0.1f, d == 0.1);
```
<details><summary>答案</summary>

输出：**`1 1`**（因为右边是同精度的同值字面量）

但要注意：
```c
printf("%d\n", 0.1f == 0.1);    // 0！float 和 double 的 0.1 二进制表示不同
float x = 0.1 + 0.2;
printf("%d\n", x == 0.3f);      // 可能是 0（精度误差）
```
**考点**：浮点不能直接用 `==` 比较，应用 `fabs(a-b) < EPS`。
`f = 0.1f` 打印 20 位小数是 `0.10000000149011611938`，证明 0.1 无法精确表示。
</details>

## Q16 sizeof 不是函数
```c
int x = 10;
printf("%zu %zu %d\n", sizeof x, sizeof(x++), x);
```
<details><summary>答案</summary>

输出：**`4 4 10`**

**关键**：`sizeof` 是**编译期运算符**，括号里的表达式**不会求值**（除非是变长数组 VLA）。
所以 `x++` 没执行，x 仍是 10。
</details>

## Q18 递归返回值
```c
int f(int n) {
    if (n == 0) return 0;

printf("%d\n", f(5));
```
<details><summary>答案</summary>

输出：**`15`**

f(5) = f(4)+5 = f(3)+4+5 = ... = 1+2+3+4+5 = 15。
（这是求 1 到 n 之和，不是阶乘）
</details>

## Q19 宏副作用
```c
#define MAX(a,b) ((a) > (b) ? (a) : (b))
int i = 5, j = 3;
printf("%d\n", MAX(i++, j++));
printf("%d %d\n", i, j);
```
<details><summary>答案</summary>

输出（macOS clang 实测）：**`6`** 然后 **`7 4`**

展开过程：`((i++) > (j++) ? (i++) : (j++))`
1. 先算条件部分：`i++` 取 5、i 变 6；`j++` 取 3、j 变 4 → 条件 `5 > 3` 为**真**
2. 真分支执行 `(i++)`：取 6、i 变 7 → 表达式结果 6
3. 整个 MAX 返回 6，i=7、j=4

**关键点**：`i` 被自增了**两次**（一次在比较、一次在真分支），`j` 自增了一次。
这是宏参数**重复求值**的经典陷阱。

**但严格说这是 UB**：同一表达式中对 i 多次修改且无序列点，不同编译器的结果**可能不同**（gcc 某些版本会给出 7 或别的值）。**实测结果只代表 clang 的行为，不能作为标准答案背**。

**正确做法**：用 inline 函数，或不要向宏传带副作用的表达式。
</details>

# 第二部分：找错题（10 题）

## Q21 返回栈变量地址
```c
char *get_msg(void) {
    char buf[64];
    strcpy(buf, "hello");
    return buf;
}
```
<details><summary>答案</summary>

**错误**：返回栈上数组的地址，函数返回后栈帧失效 → 悬空指针，使用是 UB。
**改法**（三选一）：
1. 调用方传缓冲区：`void get_msg(char *buf, size_t n)`
2. static 数组（不可重入，非线程安全）：`static char buf[64];`
3. 堆分配（调用方 free）：`char *buf = malloc(64);`
</details>

## Q22 双重释放与释放后使用
```c
void process(void) {
    char *src = malloc(10);
    char *dst = src;
    memcpy(dst, src, 20);
    free(src);
    if (src == NULL) printf("freed\n");
}
```
<details><summary>答案</summary>

**4 处错误**：
1. **未检查 malloc 返回值**（可能返回 NULL）
2. **`memcpy(dst, src, 20)` 越界**（只分配了 10 字节）
3. **dst 和 src 是同一块内存**，自己拷自己无意义（逻辑错误）
4. **free 后仍使用 src**（虽然是比较 NULL，但读已释放的指针值是 UB）；且 free 后**应主动置 NULL**，否则这个判断永远不成立
</details>

## Q23 数组越界
```c
void f(void) {
    int a[5];
    for (int i = 0; i <= 5; i++) a[i] = i;
}
```
<details><summary>答案</summary>

**错误**：`i <= 5` 时访问 a[5]，**越界**（合法下标 0~4）。
越界写会破坏栈上相邻数据（可能是返回地址/其他变量），是缓冲区溢出/崩溃的经典原因。
**改法**：`i < 5`。
</details>

```c
void f(void) {
```

## Q26 运算符优先级错误
```c
if (x & 0x0F == 0) { ... }
```
<details><summary>答案</summary>

**错误**：`==` 优先级**高于** `&`，所以实际是 `x & (0x0F == 0)` = `x & 0` = 0，条件永远为假。

## Q29 数组作函数参数丢失大小
```c
void fill(int a[]) {
```

## Q30 局部数组返回 + 编译期常量
```c
int *make_array(void) {
    static int a[10];
    return a;
}
// 调用方
int *p = make_array();
p[0] = 1;      // 这样写有问题吗？
```
<details><summary>答案</summary>

**这个写法是合法的**（static 数组生命周期是整个程序）。
**但要注意**：
1. static 数组**不可重入**（多线程/递归调用会共享同一份）
2. 多次调用返回**同一块内存**（第二次调用会覆盖第一次的结果）
3. 更好的做法：调用方传缓冲区，或堆分配

**考点**：这题是"看似有错其实没错"的反向陷阱，考的是对 static 生命周期和可重入性的理解。
</details>

# 第三部分：栈帧与函数调用（考点 + 题目）

## 3.1 栈帧（Stack Frame）是什么 ★★★

**定义**：每次函数调用时，在栈上分配的一块内存区域，存放这次调用的：
| 内容 | 说明 |
|---|---|
| **返回地址** | 调用者的下一条指令地址（由 `call` 指令压栈） |
| **保存的寄存器** | 被调用者需保存的寄存器（如 ebp/rbp、callee-saved registers） |
| **函数参数** | 部分或全部参数（取决于调用约定） |
| **局部变量** | 函数内的自动变量 |
| **临时空间** | 表达式计算的中间结果、对齐填充 |

**栈帧的创建与销毁**（x86 经典序言/尾声）：
```asm
; 函数序言 (prologue)
push ebp            ; 保存调用者的栈基址
mov  ebp, esp       ; 建立当前栈帧基址
sub  esp, N         ; 为局部变量分配 N 字节

; ... 函数体 ...

; 函数尾声 (epilogue)
mov esp, ebp        ; 恢复栈顶（丢弃局部变量）
pop ebp             ; 恢复调用者的栈基址
ret                 ; 弹出返回地址并跳转
```

**关键结论（考点）**：
1. **局部变量的"自动释放"** = 函数返回时 `mov esp, ebp` 直接把栈指针移回去，没有"删除"操作
2. **栈是向低地址增长的**（x86/ARM 都是）
3. **递归每层都新建一个栈帧** → 递归太深会**栈溢出**
4. 栈大小：Linux 默认 **8MB**（`ulimit -s` 查看，本次实测 8176KB）；MCU 上任务栈可能只有几 KB

## 3.2 传值 / 传址 / 传引用 ★★★

| 方式 | C 写法 | C++ 写法 | 效果 | 开销 |
|---|---|---|---|---|
| **传值** | `void f(int x)` | 同 | 拷贝一份，改不了原对象 | 拷贝成本（大结构体很贵） |
| **传址** | `void f(int *x)` | 同 | 能改原对象 | 一个指针 |
| **传引用** | — | `void f(int &x)` | 能改原对象，语法像传值 | 底层指针 |

**实测验证**：
```c
void swap_val(int a, int b) { int t = a; a = b; b = t; }   // 不改调用者
void swap_ptr(int *a, int *b) { int t = *a; *a = *b; *b = t; }  // 改了
```

**结构体传参的坑**（实测）：
```c
struct Big { char data[1000]; };
void take_val(struct Big b) { b.data[0] = 'X'; }   // 拷贝 1000 字节，改的是副本
void take_ptr(struct Big *b) { b->data[0] = 'Y'; } // 只传 8 字节，改的是原对象
```
**结论**：大结构体**必须传指针**（或 C++ 的 const 引用）。

**为什么函数内改变不了数组内容？** 反向陷阱：数组作为参数**退化成了指针**，所以函数内 `a[i] = x` **能**改原数组，但 `sizeof(a)` 拿不到长度。

## 3.3 递归 vs 迭代 ★★

| | 递归 | 迭代 |
|---|---|---|
| 代码 | 简洁、贴近数学定义 | 通常更长 |
| 空间 | **每层一个栈帧**，O(深度) | O(1) |
| 速度 | 有函数调用开销 | 快 |
| 风险 | **栈溢出**（深度大时） | 死循环 |

**实测递归深度**：Linux 默认栈 8MB，一个栈帧约几十~上百字节 → 大约能递归几万到十几万层。
MCU 上任务栈可能只有 512 字节~4KB → 递归几十层就溢出。

**尾递归优化**：如果递归调用是函数**最后一步**且结果直接返回，编译器可能优化成循环（不增长栈）。
```c
long fact_tail(int n, long acc) { return n <= 1 ? acc : fact_tail(n-1, acc*n); }
```
**注意**：C 标准**不要求**编译器做尾递归优化，不能依赖。

## 3.4 相关题目

### Q31 ★★★ 函数调用时栈上发生了什么？局部变量为什么能自动释放？
**答案**：
1. 调用者把参数压栈（或放寄存器），执行 `call` 把**返回地址**压栈
2. 被调用者执行序言：`push ebp` 保存调用者栈基址 → `mov ebp, esp` 建立自己的栈帧 → `sub esp, N` 给局部变量分配空间
3. 函数体执行，局部变量在 `[ebp - offset]` 处
4. 函数返回时执行尾声：`mov esp, ebp`（**栈指针直接移回，局部变量空间"消失"**）→ `pop ebp` → `ret` 弹出返回地址跳回

→ **局部变量不是被"删除"，而是栈指针移回去后那块内存不再属于这个函数**，下次调用会被覆盖。

### Q32 ★★ 传值和传址的区别？结构体参数为什么建议传指针？
**答案**：传值是拷贝一份实参，函数内修改不影响外部的原变量；传址（指针）传的是地址，函数内通过解引用可以修改原变量。
结构体传指针的原因：① **避免拷贝开销**（大结构体拷贝很贵）② 能修改原对象 ③ 但要加 `const` 防止误改。
实测：1000 字节的结构体传值要拷贝 1000 字节，传指针只传 8 字节。

### Q33 ★★ 递归和迭代怎么选？什么是尾递归？
**答案**：
递归优点：代码简洁、适合树/图的天然递归结构（遍历、分治）；缺点：栈帧开销、深度大时栈溢出、函数调用慢。
迭代优点：O(1) 空间、快；缺点：代码可能更复杂。
**尾递归**：递归调用是函数最后一步且结果直接返回，理论上可优化成循环（不增长栈）。但 C 标准不要求编译器做此优化，不能依赖。
**实践**：深度可控（如二叉树深度 <1000）用递归；深度不可控（如链表长度可能百万）用迭代。

### Q34 下面代码有什么问题？
```c
int sum_array(int a[], int n) {
    int sum;
    for (int i = 0; i < n; i++) sum += a[i];
    return sum;
}
```
**答案**：`sum` **未初始化**，在垃圾值上累加 → UB。
**改法**：`int sum = 0;`

### Q35 下面代码能正确工作吗？
```c
char *read_line(void) {
    char line[256];
    if (fgets(line, sizeof line, stdin) == NULL) return NULL;
    return line;
}
```
**答案**：**不能**。返回栈上数组地址，函数返回后失效。
**改法**：调用方传缓冲区，或 static（不可重入），或堆分配。

# 第四部分：易错速查（考前 5 分钟）

| 陷阱 | 记住 |
|---|---|
| `*p++` vs `(*p)++` | `*(p++)` 先取值再移指针；`(*p)++` 值加 1 |
| 数组作形参 | 退化为指针，`sizeof` 得 8，需要另传长度 |
| `char` 符号性 | 平台相关，字节数据用 `uint8_t` |
| 有符号/无符号混合 | 有符号转无符号，`-1` 变极大值 |
| `sizeof(x++)` | 不求值，x 不变（除非 VLA） |
| 字符串字面量 | 在 .rodata，改它崩溃；要改用 `char[]` |
| `char c[3]={'a','b','c'}` | 没有 `\0`，不是字符串 |
| 浮点比较 | 不能 `==`，用误差 |
| 位运算优先级 | 低于比较运算，`(x & 0xF) == 0` 必须加括号 |
| 宏 | 参数重复求值 + 无括号 = 两个坑 |
| 局部变量 | 不初始化就是垃圾值（全局/静态才自动清零） |
| 返回栈内存 | 悬空指针，必须改传参/static/堆 |
| 结构体赋值 | 值拷贝（浅拷贝），成员是指针则共享 |
| `free` 后 | 立即置 NULL |
| 移位 | 有符号右移是算术右移，无符号是逻辑右移 |
| 逗号表达式 | 结果是最后一个值 |
| 数组越界 | 不报错，破坏栈上相邻数据 |
